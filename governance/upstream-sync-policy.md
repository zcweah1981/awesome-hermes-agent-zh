# 官方来源同步 Policy

更新时间：2026-05-02

## 目标

这份 policy 规定内容仓如何从 Hermes 官方来源、厂商官方来源同步信息，避免中文站出现三类问题：

1. 用旧经验覆盖官方现状。
2. 把未验证的厂商说法写成确定教程。
3. 把独立站、内部治理或运行机制变成公开内容真相源。

一句话规则：

> 内容仓可以解释、翻译和重组官方信息，但不能替官方发明事实。

## 适用范围

适用于以下改动：

- Hermes Agent 安装、配置、CLI、Slash Commands、Profiles、Tools、Skills、MCP、Gateway、Automation、API Server 等页面。
- 国内模型、国内部署、国内入口页面。
- Reference 页面。
- 影响用户操作的 FAQ / Issues 页面。
- pack 安装说明中涉及 Hermes 命令、配置和目录结构的内容。

不适用于：

- 纯站点视觉文案。
- 不涉及技术事实的内容导航说明。
- 内容仓内部链接、route map、manifest 这类本仓自有合同。

## 来源优先级

1. Hermes Agent 官方文档 / 官方 GitHub。
2. 云厂商 / 模型厂商官方文档。
3. 本内容仓已经落地的 docs、packs、route map、manifest。
4. 可复现实验结果。
5. 社区文章、截图、历史笔记。

低优先级来源不能覆盖高优先级来源。

## 同步流程

### 1. 先判断是否需要同步

满足任一条件才进入官方同步：

- 官方文档 / GitHub release 有影响用户操作的变化。
- 国内模型 / 部署页面被发现信息过期。
- 用户反馈某个教程与当前官方界面或命令不一致。
- 搜索 / SEO / FAQ 摘要暴露了旧口径。

不因为“想补全一切”而大规模重写。

### 2. 查来源

每个待改页面至少确认：

- 一个 Hermes 官方来源；或
- 一个厂商官方来源；或
- 一个本仓真实文件 / route map / manifest 来源。

如果只能找到社区来源，页面只能写成“待确认 / 建议核实”，不能写成确定教程。

### 3. 做差异判断

只同步以下类型差异：

| 类型 | 是否同步 | 说明 |
|---|---:|---|
| 命令、参数、配置字段变化 | 必须 | 直接影响用户能否跑通 |
| provider / endpoint / 模型名变化 | 必须 | 直接影响模型接入 |
| 安装路径、系统依赖变化 | 必须 | 直接影响部署 |
| 官方概念命名变化 | 应同步 | 避免术语漂移 |
| 价格、额度、促销 | 谨慎 | 只写查询入口和 checked date，少复制表格 |
| 控制台 UI 截图 | 谨慎 | UI 易变，优先写路径和判断点 |
| 观点、营销说法 | 不直接同步 | 转成用户能执行的说明 |

### 4. 改中文内容

改写时遵守：

- 先告诉用户该做什么，再解释为什么。
- 明确“能得到什么结果”。
- 对可能变化的内容写“以官方控制台 / 官方文档为准”。
- 不把内部任务名、dispatch、proof、VFIX、content-cache、revalidate 写进公开正文。
- 不新增站点私有内容源；正式正文仍在内容仓。

### 5. 记录同步证据

提交说明、PR 描述或工作记录至少包含：

```text
source: <source id or URL>
checked_at: YYYY-MM-DD
affected_docs:
  - docs/...
change_type: correction | addition | removal | needs-confirmation
```

如果只做治理文件更新，不改正文，也要写清“本轮只建立规则，不同步正文事实”。

### 6. 验证

内容仓侧至少做：

- Markdown 链接不新增断链。
- 相对链接仍有效。
- 不出现敏感值。
- 如果改了 route / pack 相关字段，确认独立站可消费。

站点侧由独立站任务另行验证：manifest、search、sitemap、build。

## 国内模型页面特别规则

国内模型页容易过期，R2 必须遵守：

1. 不复制完整价格表；只说明计费类型、适合谁、去哪里确认。
2. 不承诺模型能力排行榜；只写用户决策维度：成本、速度、稳定性、上下文、兼容性、国内访问。
3. provider 兼容口径必须同时看 Hermes 官方配置口径和厂商官方 API 口径。
4. 对“OpenAI-compatible / 自定义兼容接口”要写清：能否接入取决于 endpoint、模型名、鉴权、返回格式和工具调用兼容性。
5. 每页必须有“先用哪条路线跑通”的建议，而不是只堆厂商介绍。

## 国内部署页面特别规则

国内部署页 R2 必须遵守：

1. 阿里云 / 腾讯云页面只写稳定概念和检查点：系统、SSH、端口、安全组、防火墙、Docker/Nix、进程守护。
2. 控制台路径可能变化，写“从控制台进入实例详情 / 防火墙 / 安全组”这类可迁移表述。
3. 不写死一次性活动价格。
4. 对公网 IP、端口、Token、Webhook URL 只写占位符，不写真实值。
5. 每篇教程都要有最小验收：能 SSH、能安装、能跑 Hermes、能连模型、能从一个入口使用。

## 禁止项

公开文档禁止出现：

- 未验证的官方变化。
- 未打码凭据、Token、IP 私密信息。
- “我猜 / 应该 / 可能是官方改了”这类不确定结论。
- 内部任务过程：dispatch、worker、proof、VFIX、PM Gate、runtime log。
- 站点构建机制当作 Hermes 产品能力。

## 更新节奏

R1：建立 registry、policy、R2 计划，不大规模改正文。

R2：优先同步国内模型 / 部署页面，因为这些页面最容易因厂商变化过期。

R3：Hermes 官方 docs / GitHub release 的周期巡检机制已生效。

## 验收清单

- [ ] 变更能追溯到 registry 或官方 URL。
- [ ] 页面没有未验证技术承诺。
- [ ] 页面没有敏感值和内部治理词。
- [ ] 用户能从页面知道下一步做什么。
- [ ] 如果信息不稳定，页面明确提示以官方来源为准。
- [ ] 内容仓仍是独立站唯一正式内容来源。
