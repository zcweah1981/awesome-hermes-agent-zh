# R2 国内模型 / 部署官方同步规划

更新时间：2026-05-02

## 目标

R2 的目标不是扩写“更多厂商介绍”，而是把当前 `03-国内落地` 里最容易过期的两组内容做一次官方来源同步：

1. 国内模型：确认模型接入、兼容接口、计费/套餐口径、推荐选择路径。
2. 国内部署：确认阿里云 / 腾讯云轻量服务器部署路径、SSH、安全组、防火墙、运行验收。

最终结果要让用户能回答三个问题：

- 我应该先用哪台机器跑？
- 我应该先接哪个模型或兼容接口？
- 我怎么判断自己真的跑通了？

## R2 执行顺序

### Step 1：来源确认

先为每一类页面补官方来源清单：

| 页面组 | 必查来源 |
|---|---|
| Hermes provider / custom endpoint | Hermes 官方文档、官方 GitHub |
| 阿里云百炼 | 阿里云百炼官方文档 / 控制台说明 |
| 腾讯云模型 | 腾讯云官方模型服务文档 / 控制台说明 |
| 智谱 GLM | 智谱官方开放平台文档 |
| MiniMax | MiniMax 官方开放平台文档 |
| Kimi / Moonshot | Moonshot / Kimi 官方开放平台文档 |
| DeepSeek | DeepSeek 官方 API 文档 |
| 阿里云轻量服务器 | 阿里云轻量应用服务器官方文档 |
| 腾讯云轻量服务器 | 腾讯云 Lighthouse 官方文档 |

输出：R2 工作记录中列出 URL、checked_at、对应页面。

### Step 2：页面现状审计

逐页检查：

- 是否有 frontmatter 且 description 可读。
- 是否存在过期模型名、过期套餐名、过期控制台路径。
- 是否把一次性价格 / 活动写成长期事实。
- 是否有用户可执行的“下一步”。
- 是否与 `国内落地 / 01-总览` 的推荐路径一致。
- 是否与 issues / reference 有回链。

输出：按页面列出 `keep / revise / mark-needs-confirmation`。

### Step 3：先改总览，再改细页

优先顺序：

1. `国内模型 / 01-总览`：先给用户决策树。
2. `国内部署 / 01-总览`：先给服务器路线图。
3. `DeepSeek 按量计费接口` 和 `自定义兼容接口`：优先，因为最可能成为默认跑通路径。
4. 阿里云 / 腾讯云部署教程：确保新手可按步骤跑通。
5. 其他模型厂商页：按官方来源补“适合谁 / 风险 / 下一步”。

## 关键内容规则

### 国内模型决策树

R2 总览页应给用户一个简单选择：

- 只想低成本先跑通：优先看 DeepSeek 按量计费或已有兼容接口。
- 已在某个云厂商体系内：看对应厂商模型页。
- 团队已有网关 / OneAPI / LiteLLM / OpenAI-compatible 层：看自定义兼容接口。
- 想先少改 Hermes 配置：优先选择官方文档中明确支持或兼容路径更清楚的方案。

注意：这不是模型排行，不写“最佳模型”。

### 国内部署决策树

R2 总览页应给用户一个简单选择：

- 第一次部署：选轻量服务器，先跑通 CLI。
- 已有 VPS：先跳过云厂商购买，直接检查系统、SSH、Docker/Nix、端口。
- 要团队长期用：先明确入口方式，再考虑进程守护、日志、域名、HTTPS、Gateway。
- 只在本地试用：不需要先买服务器。

### 不稳定信息处理

价格、额度、控制台 UI、模型列表容易变化，写法必须是：

- “进入官方控制台确认当前套餐 / 额度 / 模型列表”。
- “本文只给选择路径和检查点，不复制完整价格表”。
- “如厂商界面变化，以官方文档和控制台为准”。

## 交付物

R2 完成后应有：

1. 官方来源确认清单。
2. 国内模型页面修订 diff。
3. 国内部署页面修订 diff。
4. 内容自检结果：无敏感值、无内部治理词、无新增断链。
5. 站点消费验证：manifest 能正常生成，搜索摘要不出现模板句。
6. 给 Ops 的后续提醒：如果页面涉及真实 endpoint 或 API token，只能用占位符。

## 验收标准

- 每个被修改页面都能追溯到官方来源或本仓真实合同。
- 国内模型总览能帮用户选路线，而不是堆厂商名。
- 国内部署总览能帮用户选机器和部署路线，而不是只列云厂商。
- 每个细页都有“最小跑通 / 最小验收”。
- 不出现未验证价格承诺。
- 不出现真实 API Key、Token、公网 IP 私密值。
- 不出现 dispatch / proof / VFIX / 内部治理词。
- 内容仓链接检查不新增错误。
- 独立站 `verify:content` 和 `build:content` 可通过。
