# 死链检查治理

更新时间：2026-05-01（北京时间）

## 这份文档解决什么

本仓库会定期巡检公开内容中的链接。README 只保留读者入口；链接巡检的执行方式、结果查看和维护处理规则统一放在这里。

## link-check workflow 做什么

`link-check` 会检查仓库中的公开内容链接，重点覆盖：

- `README.md`
- `docs/**/*.md`
- `governance/**/*`
- `packs/**/*`
- 相关 Markdown / HTML / YAML 文件

检查结果会输出到 GitHub Actions 的 step summary，并上传报告 artifact，方便维护者复查。

## 结果怎么处理

| 类型 | 处理方式 |
|---|---|
| `404` / `410` | 优先修正文档链接或移除失效引用；如果是仓库内相对路径，必须改到真实文件。 |
| `301` / `302` | 如果新地址稳定，直接更新为最终 URL，减少读者跳转和搜索引擎重复抓取。 |
| `403` / `429` | 多为平台反爬、登录限制或 GitHub runner 限流。先用浏览器人工确认；确认不是内容问题后，再保守加入忽略规则。 |
| `timeout` | 先重跑一次检查；若连续失败，再判断是目标站不稳定、网络限制，还是需要替换来源。 |
| `fragment` / 锚点错误 | 检查目标页面标题或锚点是否变更；仓库内文档优先改成当前真实 heading 生成的锚点。 |
| 相对路径错误 | 按当前文件所在目录重新计算路径；不要为了通过检查改成不存在的旧英文目录或站点私有路径。 |

## `.lycheeignore` 边界

`.lycheeignore` 只用于保守忽略 GitHub runner 上的高频误报、反爬链接或需要认证的系统端点。

不要把这些问题加入忽略：

- 真实 `404` / `410`
- 仓库内部相对路径错误
- 图片路径错误
- 已经明确迁移到新地址的外部链接

维护原则：能修正文档就修正文档；只有确认属于检查环境误报时，才加入忽略。

## Summary 和 artifact 怎么看

1. 进入 GitHub Actions 的 `link-check` run。
2. 先看 run summary，确认失败类型和数量。
3. 如 summary 不够定位，再下载报告 artifact。
4. 按上方规则区分“真实断链”和“检查环境误报”。
5. 修复后重新触发 workflow 或等待下一次定时检查。

## 自动开 Issue 的边界

后续可以在定时检查失败时自动创建 tracking issue，但不建议把所有失败直接推给用户或维护者。

建议边界：

- 只有连续失败或确认是真实断链时才自动开 issue。
- `403` / `429` / `timeout` 这类高误报类型，应先进入 summary / artifact，不直接制造噪音 issue。
- issue 内容只记录链接、来源文件、失败类型和建议处理方式，不写入任何 token、cookie 或内部运行日志。

## 维护者下一步

- 改内容前，先确认链接是否指向当前真实路径。
- 改链接后，优先本地或通过 Actions 重新检查。
- 如果需要忽略，说明原因，并保持忽略规则最小化。
