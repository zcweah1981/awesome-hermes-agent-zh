# 自己造东西

## 这一层适合谁
- 已经完成过 starter / example 闭环的人
- 想搭自己的 Hermes 项目骨架的人
- 想把一次性尝试变成长期可维护工作流的人

## 学完能做到什么
- 会选 single-agent / team-basic / advanced-coding-team 的合适骨架
- 会整理项目目录、角色文件与项目文件
- 会用真实任务验证结构是否可维护

## 先看哪一页
1. `docs/project-structure.md`
2. `docs/project-files-guide.md`
3. `docs/soul-md-workflow.md`
4. `docs/team-basic-starter-guide.md`
5. `docs/single-agent-starter-guide.md`

## 需要准备什么
- 一个真实项目或持续任务
- 你想长期维护的目录结构
- 基本清楚的角色分工与输出边界

## 推荐动作
1. 先挑一个最接近自己的 starter 作为骨架
2. 按项目结构与项目文件指南整理目录
3. 只为当前真实任务建立最小角色分工
4. 跑一次真实任务，再决定是否扩展技能、网关或 cron

## 常见卡点
- 过早设计成大而全系统
- 目录、角色、配置边界混乱
- 把“能跑”误当成“能长期维护”
- 没用真实任务验证结构

## 完成标志
- 你已经有自己的项目骨架
- 你能把一次性尝试沉淀成可复用工作流
- 你可以进入更明确的业务场景页，而不是继续停留在起步阶段

## 下一层是什么
完成本层后，根据目标进入现成方案、国内落地、遇到问题或从 OpenClaw 过来的模块。
