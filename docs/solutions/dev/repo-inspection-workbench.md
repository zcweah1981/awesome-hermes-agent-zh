# 仓库巡检工作台

适合把一个代码仓或文档仓压成可检查、可改动、可回传的开发执行面。

## 这页解决什么问题
很多开发任务知道要改哪里，但缺少一条稳定的页面层入口与实现层落点，导致巡检、改动、回传证据都只能临时处理，无法复用。

## 页面层样板
- 页面定位：RM3 开发交付下的首个场景页
- 页面路径：`docs/solutions/dev/repo-inspection-workbench.md`
- 用户入口：仓库巡检、最小改动任务、文档补齐、结构治理需求
- 目标输出：修改文件清单、差异摘要、状态回传、下一步执行单

## 实现层样板
- 实现映射文件：`docs/solutions/dev/agents/repo-inspection-workbench-agents.md`
- 当前职责：登记推荐 agent 角色、输入输出、执行边界与后续真实脚本落点
- 当前状态：占位说明已建立，可作为后续实现层扩写入口

## 最小执行单
1. 准备一个边界清晰的仓库任务
2. 明确允许触碰的文件范围与验收标准
3. 按实现层映射选择或补齐 agent 角色
4. 产出一版真实改动，再补差异与状态回传

## 输入
- 仓库路径或任务上下文
- 允许修改的文件范围
- 验收标准
- 是否需要 diff、stat、git status

## 输出
- 修改文件清单
- 差异摘要
- git 状态回传
- 下一步执行建议

## 当前边界
- 本页只提供 RM3 的页面层+实现层双映射样板
- 不扩展到站点实现、测试、发布配置
