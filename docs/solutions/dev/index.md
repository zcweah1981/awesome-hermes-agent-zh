# 开发交付方案

适合把 Hermes 用在仓库改造、文档工程、自动化开发、调试与交付辅助上。

## 适合谁
- 正在处理代码仓库、脚本、文档或工程化问题的开发者
- 想把开发辅助从“偶尔提问”升级到“有边界的执行单”的人

## 当前问题
开发任务如果没有文件边界、验收标准和范围限制，很容易陷入分析过多、落地过少。

## 你会得到什么
- 面向开发与交付的统一入口
- 更强调文件边界、最小改动面与结果回传的执行方式
- 后续可扩展为仓库治理、文档工程、自动化脚本等场景页

## 最短开始方式
先选一个边界清晰的小任务，例如改一个 README 区块、补一份治理文件或新增一个页面骨架。

## 推荐模型或工具
优先使用终端、文件、测试与差异回传链路，先让改动可验证，再扩到更复杂的自动化。
