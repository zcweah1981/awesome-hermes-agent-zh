# 04-结合使用

很多时候，先结合使用比一上来全迁更稳。
如果你当前已经有一套在运行的 OpenClaw 生态，最好的第一步通常不是推翻重来，而是先判断 Hermes 能不能在某个高价值环节补出明显收益。

## 为什么很多时候先结合更合理

对多数真实工作流来说，最大的风险不是“迁得慢”，而是“迁得太大”。
如果你一开始就把主链路整体迁移，后面一旦遇到问题，很容易分不清到底是迁移策略错了、接入方式错了，还是试点范围本身就太大。

先结合使用更合理，是因为它能让你：

- 保留当前已经稳定运行的部分
- 只让 Hermes 进入一个高价值、可独立观察的环节
- 先验证收益，再决定是否扩大范围
- 在不伤主链的前提下，逐步建立新的使用判断

这不是保守，而是更适合真实项目的推进方式。

## 哪些能力最适合先接入

最适合先接入的，不是最复杂的能力，而是那些：

- 单点收益高
- 容易单独验证结果
- 不会一动就牵连整条现有链路
- 即使试点失败，也容易回退

也就是说，先挑“最容易证明 Hermes 有价值”的环节，而不是先挑“看起来最核心”的环节。
如果一个能力同时满足高收益、低耦合、好回退，它就更适合成为结合使用的第一站。

## 如何保留现有生态再加 Hermes

结合使用的关键，不是把 Hermes 硬塞进现有流程，而是有意识地保留原生态，再新增一个更高价值能力层。

一个更稳的思路通常是：

- 保留现在已经跑顺的主流程
- 先把 Hermes 放在一个独立价值点上
- 让新能力和旧生态并行一段时间
- 根据真实收益决定是继续扩大，还是只保留为补充能力

这样做的好处是：你不会因为一次试点失败，就把整个迁移判断都打成负面结论。
很多时候，问题不是 Hermes 没价值，而是接入位置选错了。

## 渐进试点顺序

一个更稳的试点顺序通常是：

1. 先选一个高价值、低耦合的单点环节
2. 只让 Hermes 在这个点上独立跑起来
3. 连续观察一段时间，确认收益是否真实存在
4. 只有在试点已经稳定时，才扩大到下一层

这种渐进顺序最大的价值，不是“慢”，而是你每一步都知道自己在验证什么。
一旦收益明确，后面扩大范围才有依据；如果收益不明显，也能及时止损，不会把整条原有链路一起拉进风险里。

## 常见失败方式

结合使用最常见的失败方式有：

- 第一个试点范围就太大
- 还没看清收益，就急着把 Hermes 接进主链
- 选了一个太复杂、太耦合的能力点做第一试点
- 失败后直接得出“这条路不行”的结论，而不是反思试点位置是否选错

真正需要避免的，不是试点失败，而是让第一次试点同时承担太多目标。
