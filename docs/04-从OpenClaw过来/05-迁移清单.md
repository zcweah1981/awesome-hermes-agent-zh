# 🧾 05-迁移清单

如果你已经决定迁，真正需要的不是一份大而全方案，而是一条最小试点顺序。
越是已经下定决心的人，越容易在第一步就做得过大；而真正稳的迁移，往往都是从一个可验证、可回退、可扩展的小动作开始。

## 先迁什么，不先迁什么

先迁高价值、低风险、最容易验证结果的部分；不要先迁最复杂、最核心、最难回退的部分。

一个更稳的原则是：

- 先迁能独立观察收益的环节
- 先迁失败后容易回退的部分
- 先迁不会直接拖垮现有主链的流程
- 不要把“最核心”自动等同于“最该先迁”

很多迁移失败，并不是因为能力不够，而是第一步就选错了对象。

## 最小试点顺序

把迁移拆成一个最小可验证试点，而不是一次性改完整工作流。
一个更稳的顺序通常是：

1. 先挑一个高价值、低耦合的单点环节
2. 让 Hermes 只在这个环节独立承担任务
3. 连续观察一段时间，看收益是否稳定存在
4. 只有试点通过后，再扩大到下一层

这样做的价值不是拖慢推进，而是让你每一步都知道自己到底验证了什么。

## 试点成功怎么判断

成功不是“全部替换完成”，而是试点已经证明 Hermes 在这个环节确实更有价值。
你至少要能回答下面这些问题：

- 这个试点有没有比原来更清晰的收益
- 收益是稳定出现，还是偶然碰巧
- 试点有没有引入新的不可接受成本
- 如果要扩大范围，是否已经有足够证据支撑

如果这些问题还答不清，就不该急着把试点升级成全面迁移。

## 什么时候扩大范围

只有当第一个试点已经稳定、收益明确，并且你能说清楚为什么成功时，才值得扩大。
扩大范围前，至少要满足：

- 第一个试点已经连续跑顺
- 你能明确说出收益来自哪里
- 你知道下一步扩大的是哪一层，而不是泛泛地“多迁一点”
- 你还有能力继续观察和回退

扩大范围不是奖励动作，而是基于证据的下一步。

## 最容易翻车的地方

最容易翻车的，不是动作太慢，而是一次迁太多。
常见翻车方式包括：

- 试点刚有一点效果，就立刻把主链一起迁过去
- 同时改模型、接入方式、部署和工作流，最后根本无法判断问题来自哪里
- 还没想清楚回退方案，就把原有稳定链路一起替换
- 把“我已经决定迁”误解成“可以省略试点”

真正需要避免的，不是保守，而是失去可判断性。
