# 从 OpenClaw 过来，不一定要马上迁移

如果你已经在用 OpenClaw，这一页先不劝你立刻换工具。它只解决一件事：先判断你现在更适合继续用、一起用，还是逐步迁移到 Hermes。

OpenClaw 更适合快速开始、验证想法、跑临时流程；Hermes 更适合把已经稳定的流程沉淀成可复用、可扩展、可长期运行的工作系统。

## 🎯 先记住这一页最重要的判断

从 OpenClaw 过来，不一定要马上迁移。

更稳的理解方式是：

- OpenClaw 可以继续作为探索层存在
- Hermes 更适合作为沉淀层和长期运行层存在
- 对多数用户来说，先判断、再共存、最后才决定是否迁移，通常比一上来就搬家更稳

## 🧭 先按你的当前状态选路

| 路径 | 适合谁 | 你下一步最该看什么 |
|---|---|---|
| 继续用 OpenClaw | 任务还在探索、prompt 还不稳定、只是偶尔使用、不想维护配置 | 先看 [OpenClaw 和 Hermes 的关系](./02-OpenClaw 和 Hermes 的关系.md) |
| OpenClaw + Hermes 共存 | 同类任务开始重复、prompt 开始稳定、想沉淀能力、但还不想完全迁移 | 先看 [OpenClaw + Hermes 共存指南](./04-OpenClaw + Hermes 共存指南.md) |
| 逐步迁移到 Hermes | 流程稳定、重复频繁、需要复用、自动化、协作和长期沉淀 | 先看 [继续用、共存，还是迁移](./03-继续用、共存，还是迁移.md) |

如果你只记一句：

- 还在探索 → 继续用 OpenClaw
- 任务开始稳定 → 先共存
- 流程已经稳定、值得沉淀 → 再考虑迁移

## ❗ 你可能不需要马上迁移

如果你只是偶尔用 OpenClaw 跑任务，或者还在试 prompt、试 agent、试 workflow，不需要马上迁移到 Hermes。

更好的方式通常是：

1. 先用 OpenClaw 验证需求
2. 再把稳定下来的部分逐步沉淀到 Hermes

过早迁移的代价往往不是“多花一点时间”，而是：

- 还没稳定的 prompt 被过早结构化
- 还没跑通的流程被过早抽象成 skill
- 还没验证价值的任务先背上维护成本

## 🧩 这 3 条路径到底怎么分

### 路径 A：继续用 OpenClaw
适合：

- 只是偶尔用 AI 助手
- 任务还不固定
- prompt 经常变
- 不需要团队复用
- 不想维护配置

这一阶段继续用 OpenClaw，不是落后，而是符合当前阶段。

### 路径 B：OpenClaw + Hermes 共存
适合：

- 同类任务已经做过多次
- prompt 开始稳定
- 输出格式开始固定
- 想把流程沉淀下来
- 还不想完全迁移

这是最值得优先理解的一条路。对大多数 OpenClaw 用户来说，先共存比马上迁移更稳。

### 路径 C：逐步迁移到 Hermes
适合：

- 流程已经稳定
- 需要多人复用
- 需要 skills / memory / profiles
- 需要定时执行
- 需要接飞书 / 企业微信 / 钉钉
- 需要把经验沉淀成长期资产

迁移不是为了换工具，而是为了把稳定流程变成长期可复用的系统能力。

## ⚠️ 不要把这件事理解成工具替换

错误理解：

- Hermes 替代 OpenClaw
- 用 Hermes 就不能用 OpenClaw
- OpenClaw 跑通的东西必须全部搬过来
- 迁移是第一步

正确理解：

- OpenClaw 是实验场
- Hermes 是沉淀层
- 共存是最稳的升级方式
- 只迁移稳定流程
- 迁移不是搬家，而是把经验做成 Hermes 可长期维护的结构
