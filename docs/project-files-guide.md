# Hermes 项目文件编写指南（PROJECT / TASKS / DECISIONS）

如果目录结构解决的是“文件放哪”，那这篇解决的是“文件怎么写”。

---

## 1. PROJECT.md 写什么

建议只写三类信息：
- 目标是什么
- 当前范围是什么
- 验收标准是什么

不要把 PROJECT.md 写成日记，也不要把所有细节都塞进去。

---

## 2. TASKS.md 写什么

TASKS.md 要解决的是执行问题。

建议每项至少有：
- 任务名
- 负责人
- 输入
- 输出
- 状态

这样才适合团队协作和交接。

---

## 3. DECISIONS.md 写什么

它用来记录关键取舍，例如：
- 为什么优先官方 provider
- 为什么 starter 和 example 分离
- 为什么某个功能延期

没有这份文件，后面的人只会反复重开旧讨论。

---

## 4. CHANGELOG.md 写什么

只记录对外交付变化，例如：
- 新增什么页面
- 新增什么模板
- 修复了什么入口问题

不要把内部碎碎念写进去。

---

## 推荐写法原则

- 每个文件只管一类问题
- 一页只服务一个目的
- 用最少字段保持清晰
