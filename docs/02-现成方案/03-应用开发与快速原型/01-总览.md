# 01-总览｜应用开发与快速原型

> 一句话先说清楚：这一层不是教你系统学前端或后端，而是帮你先挑一套已经能直接试跑的开发原型方案，把一个想法先压成第一版可开工结构。

## 👀 这一层现在有什么

当前这一层已经能直接进入 2 套现成方案：

- [02-微信小程序助手](./02-微信小程序助手.md)
- [03-敏捷 Web 开发助手](./03-敏捷 Web 开发助手.md)

如果你现在的目标是：
- 我手里有一个产品想法，想先把页面、目录、接口和骨架压出来
- 我不想先自己从 PRD、页面清单、接口设计一路手拆
- 我更关心“今天能不能开工”，而不是先补一套完整开发方法论

那就直接从这一层进。

## 🧩 这两套方案分别解决什么

### 微信小程序助手
适合你想先做：
- 一个报名、展示、表单、工具类微信小程序
- 第一版页面清单、目录骨架、接口占位和首批文件建议
- 从产品想法直接推进到“能开始搭代码”的状态

直接进入：
- [02-微信小程序助手](./02-微信小程序助手.md)

### 敏捷 Web 开发助手
适合你想先做：
- 一个后台、控制台、表单系统或内部运营工具
- 第一版页面结构、数据结构、接口草案和前端骨架
- 从业务想法直接推进到“能开始搭原型”的状态

直接进入：
- [03-敏捷 Web 开发助手](./03-敏捷 Web 开发助手.md)

## 🗺 默认主线

如果你不想自己选，最稳的顺序是：

1. 如果目标是微信生态里的轻应用，先走 [02-微信小程序助手](./02-微信小程序助手.md)
2. 如果目标是浏览器里的后台、控制台或管理工具，再走 [03-敏捷 Web 开发助手](./03-敏捷 Web 开发助手.md)

最简单的判断方式是：
- 面向微信用户、入口在微信里 → 小程序
- 面向浏览器、入口在网页里 → Web 原型

## ✅ 看完这页你应该立刻能判断什么

看完后，你应该能马上判断：
- 我现在更适合先做微信小程序，还是先做 Web 原型
- 我更需要页面骨架、目录结构，还是后台页面与接口草案
- 我下一步该不该直接进小程序页，还是 Web 开发助手页
