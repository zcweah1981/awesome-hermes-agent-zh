# 02-微信小程序助手

> 一句话定位：这个方案帮助想快速把微信小程序想法变成“可开工实现包”的用户，先拿到一套默认可跑的 agent 方案，而不是从空白文档自己拆需求。

---

## 1. 这是什么方案

### 核心场景
你已经明确要做一个微信小程序，但还不想在“先写代码、先画页面、先想接口、先搭目录”之间来回打转。这个方案直接给你一个现成可用的 agent 路径，把需求先压成可开工实施包。

### 最终结果
你最后会拿到一套能直接进入开发的结构化输出，至少包括：页面清单、功能清单、数据结构建议、接口建议、开发顺序、测试检查单；如果走团队协作版，还会拆成多 Agent 最小交接包。

### 页面定位
这是一个可直接应用的方案页，不是教程页，也不是概念页。重点不是教你学会微信小程序，而是让你拿到就能用一个现成方案，把“活动报名微信小程序 MVP”先跑起来。

---

## 2. 适合谁

### 适合谁
- 已经有明确小程序想法，但不想自己从零拆 PRD 的个人开发者
- 想让 Hermes 直接先给出可开工结构，而不是泛泛建议的人
- 想验证“单 Agent 能不能先跑通”“多 Agent 协作有没有必要”的小团队

### 更适合什么阶段的人
- 新手先跑通：已经知道要做小程序，但还没有一套开工结构
- 已经有基础、想提效：希望用 Agent 先把页面、功能、接口、测试拆清楚
- 小团队开始协作：希望把产品、实现、接口、测试先变成明确交接包

---

## 3. 你要准备什么

### 最少准备项
- 一个明确的小程序主题
- 一个最小目标用户场景
- 一个愿意先只做 MVP 的范围边界

### 标准输入
- 业务目标：例如“做一个活动报名微信小程序”
- 场景说明：例如“社群活动发布后，用户能报名、查看时间地点、查看报名结果”
- 约束条件：例如“先不接支付、不做复杂后台、不做裂变”

### 标准输出
- 页面清单
- 功能清单
- 数据结构建议
- 接口建议
- 开发顺序
- 测试检查单
- 超级个体版 / 团队协作版执行方案

## 5. 默认推荐

### 默认入口
- ACP / CLI

### 默认模型
- 默认推荐：稳定的长上下文编码模型（如 Claude Sonnet 级）
- 备选推荐：稳定的国产编码模型（如 GLM-4.5-Air / DeepSeek-V3.1 级）

### 默认使用方式
如果你现在最想先拿到一个能直接开工的 MVP 结构包，默认先走“超级个体版”：
- 在 ACP 或 CLI 里触发单 Agent
- 直接产出页面、功能、接口、测试四层结构
- 再由你人工确认是否继续实现

如果你已经确定要团队协作，就不要让一个 Agent 既做产品拆解、又做页面实现、又做接口设计、又做测试验收，而是直接切到“团队协作版”的多 Agent 路线。

### 默认实现方式
- 超级个体版默认下载包：`packs/miniapp-lab/01-super-individual.zip`
- 团队协作版默认下载包：`packs/miniapp-lab/02-team.zip`
- 团队协作版 zip 内已包含：产品、实现、接口、测试、validator 五个目录，不需要用户分别下载很多内容

## 6. 5 分钟跑通

### 用户怎么使用
1. 先下载 `01-super-individual.zip` 或 `02-team.zip`
2. 解压后进入对应目录，而不是在仓库里分别找很多子包
3. 先创建目标 profile，再执行 zip 内自带的安装脚本
4. 用现成 sample-input 触发一次，确认输出真的包含页面、功能、数据、接口、顺序、测试六类结果

### 最小触发方式
- 命令 / Slash command / 平台消息触发：

#### 超级个体版下载后安装
```bash
cd /path/to/01-super-individual
hermes profile create miniapp-solo --clone
bash ./install_to_profile.sh miniapp-solo
```

#### 超级个体版运行
```bash
miniapp-solo chat --skills wechat-mini-program-solo-assistant -q "$(cat skills/solutions/wechat-mini-program-solo-assistant/examples/sample-input.md)"
```

#### 团队协作版下载后安装
```bash
cd /path/to/02-team
hermes profile create miniapp-product --clone
hermes profile create miniapp-builder --clone
hermes profile create miniapp-api --clone
hermes profile create miniapp-qa --clone
hermes profile create miniapp-validator --clone
bash ./install_all.sh
```

### 跑通后你会看到什么
- 结果 1：不是泛泛建议，而是一份结构化 MVP 实施包
- 结果 2：你能直接看清 MVP 边界有没有失控
- 结果 3：你能明确决定这件事是一个 Agent 先干，还是切成多 Agent 协作

## 7. 超级个体版 / 团队协作版

### 超级个体版

#### 定义
一个 Agent 独立把“小程序从想法整理成可开工实现包”的版本。

#### 最小流程
1. 用户输入业务目标、目标用户、最小闭环和约束
2. `wechat-mini-program-solo-assistant` 输出页面清单、功能清单、数据结构建议、接口建议、开发顺序、测试检查单
3. 用户人工确认 MVP 边界
4. 再决定是否进入真实开发或切到团队协作版

#### 交付结果
- 最终拿到什么：一份可直接开始做的 MVP 实施包
- 哪一步需要人工确认：范围取舍、是否真的先不做支付/后台/裂变

### 团队协作版

#### 是否建议首批上线
- 建议

#### 最小角色
- 角色 1：产品拆解 Agent
- 角色 2：小程序实现 Agent
- 角色 3：接口设计 Agent
- 角色 4：测试验证 Agent

#### 最小交接顺序
1. 产品拆解 Agent 产出页面清单、功能清单、范围边界
2. 小程序实现 Agent 接收页面与交互结构，补前端实现顺序
3. 接口设计 Agent 接收数据结构与页面需求，补 API 与字段清单
4. 测试验证 Agent 用 runbook 和 checklist 判断这套输出是否可开工

#### 团队版交付物
- 中间产物 1：页面与功能结构表
- 中间产物 2：接口与数据结构建议
- 最终交付物：可进入开发排期的 MVP 多 Agent 实施包
