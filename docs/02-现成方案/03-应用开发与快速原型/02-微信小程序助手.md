# 02-微信小程序助手

> 先说结论：这一页不是教你研究小程序原理，也不是只帮你写一份方案文档；它的目标是让你直接调用现成 skill，把一个微信小程序想法压成“可开工代码骨架 + 实施包”。

---

## 1. 这一页到底能帮你做什么

如果你现在脑子里只有一句话需求，比如：
- 我想做一个活动报名微信小程序
- 我想先把 MVP 跑起来
- 我不想先自己写 PRD、画流程、搭目录

那这一页要解决的就是：
- 帮你把一句话需求变成可开工输出
- 默认直接给出代码骨架思路，而不是停在抽象建议
- 让你能判断：先用一个 Agent 直接搭，还是拆给多个 Agent 协作

这页的默认目标不是“给你一份好看的策划案”，而是让 Hermes 往前走一步，直接产出适合开始开发的内容。

你应该期待的最终结果是：
- 页面与路由清单
- 数据与接口草案
- 关键页面文件建议
- 小程序项目骨架建议
- 首批要生成的代码文件/目录
- 测试与验收清单

---

## 2. 这页适合谁

适合这三类人：

### 1）你有想法，但不想从空白开始
例如你已经知道要做“活动报名”“预约”“表单收集”“社群工具”这类小程序，但还不想自己先拆需求。

### 2）你要的是“直接往代码走”
你不想先看一堆泛泛建议，而是希望 Hermes 先给你：
- 怎么建目录
- 先出哪些页面
- 每个页面先写什么
- 哪些接口先留 stub

### 3）你在判断单 Agent 够不够
如果你的项目还不复杂，先用一个 Agent 直接把骨架搭出来，通常最快；如果你已经准备多人协作，才切到团队版。

不适合的情况：
- 你现在要的是完整 UI 视觉设计稿
- 你现在要的是完整后端上线部署方案
- 你现在要的是支付/会员/裂变/复杂后台一起上

这一页默认只解决：先把 MVP 搭起来。

---

## 3. 你调用之后，Hermes 应该产出什么

为了让这页更清楚，这里直接说“应该拿到什么”，而不是讲抽象结构。

### 最小可用输出
调用 skill 后，至少应该拿到下面 6 类内容：

1. 页面清单
- 首页/列表页
- 详情页
- 表单页
- 结果页

2. 数据结构草案
- 活动对象有哪些字段
- 报名对象有哪些字段
- 哪些字段前端先写死，哪些后面接接口

3. 接口草案
- 获取活动列表
- 获取活动详情
- 提交报名
- 查询报名结果

4. 代码骨架建议
- `pages/`
- `components/`
- `services/`
- `utils/`
- `app.json`
- `app.js`
- 页面级 `.wxml / .wxss / .js / .json`

5. 首批实现顺序
- 先把页面路由跑通
- 再补假数据
- 再补提交逻辑
- 最后替换成真实接口

6. 验收清单
- 页面能打开
- 路由不报错
- 表单能提交
- 假数据能跑通
- 后续替换接口的位置清楚

### 这一页真正要交付给用户的不是“分析”，而是这类可执行输出
所以你可以把它理解成：
- 先由 Hermes 帮你搭第一版小程序开工骨架
- 再由你决定要不要继续细化、补代码、拆角色

## 4. ACP 和 CLI 在这里分别有什么用

前一版这里写得太虚，这里直接说人话。

### ACP 是干什么的
ACP 更适合你已经在编辑器里准备开始做项目的时候用。

你可以把它理解成：
- 让 Hermes 直接在你的开发环境里干活
- 更适合一边看目录、一边让它补文件、补代码、补说明
- 如果你想让它继续往“真正生成文件骨架”走，ACP 比纯聊天更顺手

适合场景：
- 你已经在 VS Code / IDE 里
- 你准备真的开始搭项目
- 你希望它按目录逐步生成内容

### CLI 是干什么的
CLI 更适合先快速验证这个 skill 值不值得用。

你可以把它理解成：
- 先在终端里试跑一次
- 看它输出是不是靠谱
- 适合先用 sample-input 验证方向

适合场景：
- 你还在试方案
- 你想先看输出质量
- 你还没进入正式工程目录

### 默认建议
- 先用 CLI 跑通一次，确认这个 skill 给的骨架方向对不对
- 确认对了，再切 ACP 或编辑器环境继续往代码文件推进

也就是说：
- CLI = 先试跑
- ACP = 继续实做

## 5. 5 分钟先跑通一次

现在默认交付是两个 zip：
- `packs/miniapp-lab/01-super-individual.zip`
- `packs/miniapp-lab/02-team.zip`

如果你只是先验证“一个 Agent 能不能把小程序骨架搭出来”，先下载：
- `01-super-individual.zip`

### 第 1 步：解压并进入目录
```bash
cd /path/to/01-super-individual
```

### 第 2 步：创建独立 profile
```bash
hermes profile create miniapp-solo --clone
```

### 第 3 步：安装这个 skill 包
```bash
bash ./install_to_profile.sh miniapp-solo
```

### 第 4 步：先用现成输入跑一次
```bash
miniapp-solo chat --skills wechat-mini-program-solo-assistant -q "$(cat skills/solutions/wechat-mini-program-solo-assistant/examples/sample-input.md)"
```

### 跑完你应该重点看什么
不要只看它“说了很多话”，而要看有没有这几类东西：
- 页面文件怎么搭
- 目录怎么起
- 假数据怎么先跑
- 接口 stub 放哪里
- 第一批代码先写哪些文件

如果只有概念分析，没有往代码骨架走，这一页就不算达到目标。

### 跑通之后，马上怎么把它推进成真实代码
如果 CLI 这一步的输出方向对了，下一步不要继续空聊，而是直接把它带进 ACP / 编辑器环境，开始补文件。

你可以直接按下面这种方式继续下指令：

```text
基于刚才这版活动报名小程序骨架，继续往可运行代码走：
1. 先创建 miniprogram 目录结构
2. 先生成 app.json、app.js、app.wxss
3. 先生成 pages/activity-list/index.js、index.wxml、index.wxss、index.json
4. 先生成 pages/activity-detail/index.js、index.wxml、index.wxss、index.json
5. 先生成 utils/mock.js 和 services/activity.js
6. 所有数据先用 mock，不接真实后端
7. 每生成一组文件，都说明这个文件负责什么
```

### 一个合格的 ACP 续跑结果，至少应该做到什么
- 真正开始落文件，而不是重复讲方案
- 先把目录和基础文件补出来
- 生成的页面文件之间能看出跳转关系
- `services/` 和 `utils/` 有明确分工
- 明确哪些地方现在是 mock，后面再换接口

你可以把这一段理解成：
- CLI 负责先证明方向对
- ACP 负责把方向变成第一版真实文件

## 6. 默认主线：先让一个 Agent 把代码骨架搭出来

如果你现在没有明确的多人协作需求，默认直接走超级个体版。

### 超级个体版在这里的定义
不是“一个 Agent 帮你整理思路”就结束。

而是：
- 一个 Agent 接收你的需求
- 先压出 MVP 边界
- 再给出小程序项目骨架
- 再告诉你第一批代码应该怎么起

### 推荐你怎么下指令
你给它的输入，尽量包含 4 件事：
- 做什么
- 谁来用
- 最小闭环是什么
- 先不做什么

例如：
- 做一个活动报名微信小程序
- 用户是社群活动参与者
- 最小闭环是：看活动、填表单、提交报名、看到结果
- 先不做支付、会员、裂变、复杂后台

### 你最终应该拿到的内容
一个合格输出，至少应该像下面这样：
- 小程序目录结构建议
- 页面文件列表
- 页面之间的跳转关系
- 假数据结构
- API stub 设计
- 第一轮开发顺序
- 哪些地方可以让 ACP 继续补代码

这才叫“帮你开始搭代码”，不是只给一个策划提纲。

## 7. 什么时候切到团队协作版

当你已经确认这件事不是一个 Agent 一把梭能干完时，再切团队版。

团队版不是为了显得高级，而是为了把职责拆清楚。

### 团队版分别做什么
- `01-product`：把场景压成页面、功能、边界、交接物
- `02-builder`：把页面与交互变成前端实现骨架
- `03-api`：把数据结构和接口约定拆清楚
- `04-qa`：检查这套东西是不是真的可开工
- `99-solution-validator`：最后做总体验收

### 团队版什么时候值得用
适合这三种情况：
- 你准备多人协作
- 你不想让一个 Agent 同时兼顾产品、实现、接口、验收
- 你已经准备把输出继续推进成正式开发任务

### 团队版怎么装
先下载：
- `packs/miniapp-lab/02-team.zip`

解压后进入：
```bash
cd /path/to/02-team
```

创建 profile：
```bash
hermes profile create miniapp-product --clone
hermes profile create miniapp-builder --clone
hermes profile create miniapp-api --clone
hermes profile create miniapp-qa --clone
hermes profile create miniapp-validator --clone
```

安装：
```bash
bash ./install_all.sh
```

如果你现在只是第一次试这套方案，不建议一上来就团队版；先把单 Agent 跑通更重要。
