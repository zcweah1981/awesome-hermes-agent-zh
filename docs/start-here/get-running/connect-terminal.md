# 进入终端并连接服务器

这一步完成后，你应该已经站在一个可以继续安装 Hermes 的终端里，并且确认 Git 可以正常使用。

## 第 1 步：先确认你走哪条路线

你现在只需要从下面 3 条路线里选 1 条：

| 你的环境 | 这一步该做什么 |
| --- | --- |
| 本地 macOS / Linux | 打开本机终端 |
| Windows WSL2 | 进入 WSL2 的 Linux 终端 |
| 云主机 | 通过 SSH 登录远程服务器 |

为什么先做这一步：
- 后面的操作会因为路线不同而不同。

看到什么算成功：
- 你已经明确自己接下来是“打开本地终端”“进入 WSL2”还是“SSH 登录远程服务器”。

如果没看到这个结果，先检查什么：
- 你是不是还没确定 Hermes 到底装在本地还是云主机。

## 第 2 步：进入正确的终端

### 路线 A：本地 macOS / Linux

现在做什么：
- 打开系统终端。
- macOS 可以用 Terminal 或 iTerm2。
- Linux 直接打开系统自带终端。

为什么做这一步：
- 你后面的安装命令必须在真正的终端里执行。

看到什么算成功：
- 你已经看到一个可以输入命令的终端窗口。
- 屏幕上有提示符，光标停在下一行等待输入。

如果没看到这个结果，先检查什么：
- 你是不是打开了别的程序，而不是终端。
- 终端是不是没有正常启动。

### 路线 B：Windows WSL2

现在做什么：
- 启动 WSL2 的 Linux 发行版终端。

为什么做这一步：
- 这套教程后面的命令按 Linux 终端来执行，不是在 PowerShell 或 CMD 里执行。

看到什么算成功：
- 你已经进入 Linux 终端。
- 提示符看起来是 Linux 风格，可以继续输入 Linux 命令。

如果没看到这个结果，先检查什么：
- 你是不是还停留在 PowerShell 或 CMD。
- WSL2 是否已经正确安装并能启动。

### 路线 C：云主机 SSH 登录

#### 第 2.1 步：先准备登录信息

现在做什么：
- 把这 3 样东西准备好：
  - 服务器公网 IP
  - 登录用户名
  - 登录密码，或者密钥文件路径

为什么做这一步：
- SSH 登录需要这 3 样信息，少一项都无法继续。

看到什么算成功：
- 你已经能直接拼出完整登录命令。

如果没看到这个结果，先检查什么：
- 公网 IP、用户名、密码或密钥是不是还没拿到。

#### 第 2.2 步：执行 SSH 登录命令

现在做什么：
- 如果你用密码登录，执行：

```bash
ssh 用户名@服务器IP
```

- 例如：

```bash
ssh root@你的服务器IP
```

- 如果你用密钥文件登录，执行：

```bash
ssh -i /你的密钥路径 用户名@服务器IP
```

- 例如：

```bash
ssh -i ~/.ssh/你的密钥文件 root@你的服务器IP
```

为什么做这一步：
- 你要先真正进入服务器，后面的安装才是在正确机器上完成。

看到什么算成功：
- 终端开始执行 SSH 连接。
- 第一次连接时，可能会出现主机指纹确认提示。

如果没看到这个结果，先检查什么：
- 用户名和 IP 有没有写错。
- 密钥路径有没有写错。
- 你是不是把本地终端和远程终端搞混了。

#### 第 2.3 步：完成第一次连接确认并进入服务器

现在做什么：
- 如果是第一次连这台服务器，看到是否信任主机指纹的提示后，确认无误再输入 `yes`。
- 接着输入密码，或等待密钥认证完成。

为什么做这一步：
- 只有真正进入远程 shell，才说明 SSH 登录成功。

看到什么算成功：
- 终端提示符已经变成远程服务器的用户和主机名。
- 你已经处在远程 shell 里，可以继续输入命令。

如果没看到这个结果，先检查什么：
- 服务器是否允许 SSH 登录。
- 安全组、防火墙是否放行 SSH 端口。
- 密码、密钥是否正确。

## 第 3 步：确认你真的已经进入目标环境

现在做什么：
- 在当前终端执行：

```bash
pwd
whoami
```

为什么做这一步：
- 你要确认自己现在确实站在目标环境里，而不是进错地方或根本没连上远程服务器。

看到什么算成功：
- `pwd` 会返回当前目录。
- `whoami` 会返回当前用户。
- 如果你走的是云主机路线，当前用户和提示符应该已经是远程服务器上的用户，而不是你本地机器上的用户。

如果没看到这个结果，先检查什么：
- 你是不是根本还停留在本地终端。
- 你是不是开错了窗口，或者 SSH 没有真正登录成功。

## 第 4 步：检查 Git 是否可用

现在做什么：
- 执行：

```bash
git --version
```

为什么做这一步：
- 后面的安装流程依赖 Git 可用。

看到什么算成功：
- 屏幕上出现 Git 版本号，例如 `git version 2.x.x`。
- 命令执行后，提示符回到下一行，可以继续输入下一条命令。

如果没看到这个结果，先检查什么：
- Git 是否还没安装。
- 当前终端是否有权限正常执行 Git。

## 第 5 步：如果 Git 还没装，先装好再复查

### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y git
```

### CentOS / Rocky / AlmaLinux

```bash
sudo yum install -y git
```

如果你的系统使用 `dnf`，也可以执行：

```bash
sudo dnf install -y git
```

### macOS

第一次执行 `git` 时，系统通常会提示安装开发者工具。按提示完成安装后，再重新执行一次：

```bash
git --version
```

为什么做这一步：
- 只有安装后再复查一次，才能确认这一页真的通过。

看到什么算成功：
- 你再次执行 `git --version` 时，已经能看到版本号。

如果没看到这个结果，先检查什么：
- 安装命令有没有执行成功。
- 你是不是还没回到正确终端。
- 当前系统的软件源或网络是否有问题。

## 这一步完成后，你应该看到什么

满足下面两件事，就可以继续下一页：

1. 你已经进入了正确的终端环境。
2. 你执行 `git --version` 时已经看到版本号。
