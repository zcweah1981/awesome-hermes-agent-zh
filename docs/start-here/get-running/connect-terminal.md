# 进入终端并连接服务器

在安装 Hermes 之前，你需要先进入正确的终端环境。
如果你是本地运行，这一步通常是打开终端；如果你准备把 Hermes 装在云主机上，这一步通常是通过 SSH 登录服务器。
离开这页时，你应该已经进入一个可以继续安装 Hermes 的终端环境，并确认 Git 已经可用。

---

## 1. 页面定位

这是“先跑起来”阶段的第二步。
它不负责安装 Hermes，也不负责配置模型，只负责帮你进入正确终端，并在需要时连接到服务器。

1. 已经打开本地终端，或者成功连上 Linux 服务器

3. 已经确认 Git 可以正常使用

## 5. 页面结构

### 5.1 先判断你属于哪种情况

| 你的情况 | 你这一步要做什么 |
|---|---|
| 本地 macOS | 打开终端 |
| 本地 Linux | 打开终端 |
| 云主机 | 通过 SSH 登录服务器 |
| Windows WSL2 | 先进入 WSL2，再打开终端 |

### 5.2 本地运行：先打开终端

#### macOS

macOS 自带 Terminal，也可以使用 iTerm2。
如果你只是准备在本地先跑一次，打开其中任意一个都可以。

#### Linux

大多数 Linux 发行版都自带终端，直接打开即可。

#### Windows WSL2

如果你走的是 WSL2 路线，先进入 WSL2 环境，再继续后面的命令。
如果 WSL2 还没准备好，请先返回上一页提到的环境准备占位链接补齐。

### 5.3 云主机：推荐使用哪些工具

#### Windows 用户常见选择

- Windows Terminal
- PuTTY
- Tabby

#### macOS 用户常见选择

- Terminal
- iTerm2
- Tabby

工具本身不是重点，重点是：你能稳定打开一个终端，并把命令发到目标服务器上。

### 5.4 什么是 SSH

SSH 可以理解成：从你的电脑进入远端 Linux 服务器的标准方式。
通常你至少要准备下面这些信息：

- 服务器公网 IP
- 登录用户名
- 登录密码，或者密钥文件

### 5.5 最基础的连接命令

如果你使用用户名和地址直接登录：

```bash
ssh 用户名@服务器IP
```

如果你需要带密钥文件：

```bash
ssh -i /你的密钥路径 用户名@服务器IP
```

第一次连接时，如果系统询问是否继续连接，确认服务器信息无误后继续即可。

### 5.6 一个最典型实例：Ubuntu 服务器 SSH 登录

最常见、也最适合作为示例的情况是：你手上有一台 Ubuntu 云主机，现在需要从本地电脑连进去。

你拿到公网 IP、用户名和登录方式后，进入终端执行：

```bash
ssh 用户名@服务器IP
```

如果连接成功，你会看到终端提示符已经切换到远程服务器环境。到这里，这一步最核心的目标就达成了。

### 5.7 开始安装前，先确认 Git 已经准备好

先执行：

```bash
git --version
```

如果能返回版本号，说明 Git 已经可用，可以继续下一页。

### 5.8 如果 Git 还没有安装，怎么办

#### Ubuntu / Debian

```bash
sudo apt update
sudo apt install -y git
```

#### CentOS / Rocky / AlmaLinux

```bash
sudo yum install -y git
```

或者：

```bash
sudo dnf install -y git
```

#### macOS

很多情况下，第一次执行 `git` 时系统会提示你安装开发者工具，按提示完成即可。

### 5.9 连接失败时先做最小检查

如果你现在还连不上，不要立刻进入复杂排障，先检查最小集合：

- 服务器公网 IP 有没有填错
- 用户名有没有填错
- 密码或密钥文件是否正确
- 你现在连的是不是正确的服务器
- 网络是否能访问这台服务器

这一页只做最小检查；更完整的排障后面统一放到“遇到问题”模块。

当你已经进入正确终端，并且 `git --version` 能正常返回时，就继续：
