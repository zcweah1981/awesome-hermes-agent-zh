# 把 Hermes 装上去

现在你已经进入了运行环境，并且确认 Git 已经可以正常使用，下一步就是把 Hermes 装上去。  
**离开这页时，你应该已经完成 Hermes 安装。**

---

## 1. 页面定位

这是“先跑起来”模块的第 3 页。  
它的任务是把 Hermes 安装到当前环境里，并确认它已经安装成功。

---

## 2. 页面目标

用户离开这页时，应该完成：

1. 已经执行 Hermes 安装  
2. 已经确认 Hermes 安装成功  

---

## 3. 解决什么问题

- 官方推荐安装方式
- 最短安装命令
- 安装成功后怎么验证

## 5. 页面结构

### 5.1 官方推荐安装方式

建议优先使用 Hermes 官方的一键安装方式。

现在做什么：
- 不要先绕去手动安装、也不要先自己补一堆依赖。
- 这一步先走官方最短路径。

为什么做这一步：
- 对第一次安装来说，官方一键安装是最稳、最短、最容易闭环验证的路径。

看到什么算成功：
- 你已经决定这一页直接用官方一键安装命令继续。

如果没看到这个结果，先检查什么：
- 你是不是还在犹豫要不要先手动装 Python / Node / uv。
- 你是不是还没回到上一页确认 Git 已经可用。

### 5.2 直接开始安装

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

![Hermes 安装执行截图：在终端里输入官方一键安装命令，并已经开始出现安装输出](../assets/rm2-2-install-hermes-01-install-command-running.png)

现在做什么：
- 在当前终端里执行上面的官方安装命令。

为什么做这一步：
- 这条命令会按官方推荐流程开始安装 Hermes，并自动处理主要安装步骤。

看到什么算成功：
- 终端已经开始出现安装输出。
- 你能看到安装器启动、环境检查、依赖检查或下载相关信息。
- 命令没有一开始就停在明显的报错上。

如果没看到这个结果，先检查什么：
- 安装命令是不是完整复制了。
- 当前网络是否正常。
- 你是不是在正确的 Linux / macOS / WSL2 终端里执行。

### 5.3 安装完成后重新加载终端环境

先执行下面这条命令，确认你当前用的是哪种 shell：

```bash
echo $SHELL
```

如果结果里是 Bash，再执行：

```bash
source ~/.bashrc
```

如果结果里是 Zsh，再执行：

```bash
source ~/.zshrc
```

现在做什么：
- 先用 `echo $SHELL` 判断自己当前是 Bash 还是 Zsh。
- 再执行对应的 `source` 命令重新加载 shell。

为什么做这一步：
- 安装结束后，重新加载 shell 才能让新的 `hermes` 命令立刻生效。

看到什么算成功：
- `echo $SHELL` 已经让你明确知道自己当前用的是哪种 shell。
- `source` 命令执行后没有报错。
- 终端回到提示符，允许继续输入下一条命令。

如果没看到这个结果，先检查什么：
- 你是不是搞错了自己当前使用的 shell。
- 对应的配置文件是否存在。
- 你是不是执行了和当前 shell 不对应的 `source` 命令。

### 5.4 检查有没有安装成功

先执行：

```bash
hermes version
```

再执行：

```bash
hermes doctor
```

![Hermes 安装成功截图：已经可以执行 hermes version 和 hermes doctor，并看到正常输出](../assets/rm2-2-install-hermes-02-version-and-doctor-success.png)

现在做什么：
- 先执行 `hermes version`。
- 再执行 `hermes doctor`。

为什么做这一步：
- 只有这两条命令都能正常工作，才说明安装真正完成，而且当前环境适合进入下一步。

看到什么算成功：
- `hermes version` 返回真实版本信息。
- `hermes doctor` 完成检查，并给出可继续使用的结果。
- 执行完后，终端回到提示符，可以继续下一页。

如果没看到这个结果，先检查什么：
- 如果 `hermes version` 提示 `command not found`：说明 shell 还没正确重新加载，或者 PATH 还没生效。
- 如果 `hermes doctor` 报错：先按它给出的提示修当前环境，再重新执行一次。

### 5.5 安装失败时先看什么

- 安装命令是否完整复制
- 网络是否正常
- 当前终端环境是否正确
- Git 是否已经可用
- 是否有明显报错信息

现在做什么：
- 只要有一步没过，就先回到这一组最小检查，不要直接跳到模型配置页。

为什么做这一步：
- 这一页的目标不是“命令跑过”，而是“安装已经真正完成并可继续下一页”。

看到什么算成功：
- 你已经定位到问题是在命令、网络、终端环境、Git，还是 shell 生效这几个基础项之一。

如果没看到这个结果，先检查什么：
- 你是不是还没有把当前报错落到具体一项。
- 你是不是在安装没闭环之前就想往下一页跳。

### 5.6 成功界面是什么样子

当你看到下面两件事同时成立，就说明这一页已经通过：

1. 终端已经能识别 `hermes` 命令。  
2. 你执行 `hermes version` 和 `hermes doctor` 时，都已经看到正常输出。
