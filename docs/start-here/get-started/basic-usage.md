# 认识 Hermes 的基本使用方式

你已经完成第一次互动了，接下来要学的是：Hermes 平时到底怎么用。  
**离开这页时，你应该已经知道怎样启动 Hermes、怎样直接提问，以及最常用的几个基础动作是什么。**

---

## 🚪 平时怎么启动 Hermes

![真实终端主入口截图：在 Linux 终端执行 `hermes` 后，已经进入 Hermes 交互主入口并停在可继续输入的提示符位置](../assets/rm2-3-basic-usage-01-cli-main-surface.png)

最常见的日常入口只有一个：

```bash
hermes
```

现在做什么：
- 在你已经安装好 Hermes 的终端里输入 `hermes`。

为什么做这一步：
- 这是最统一、最稳定的日常主入口。
- 后面不管你是提问、继续追问，还是查看命令，都是从这里开始。

看到什么算成功：
- 你已经进入 Hermes 的交互状态。
- 终端没有停在 `command not found` 这类报错上。
- 你知道：以后平时要用 Hermes，先回到这个入口。

如果没看到这个结果，先检查什么：
- 你是不是还没完成上一页里的 `hermes version` 和 `hermes doctor`。
- 你是不是在错误终端里执行了命令。

---

## ⚡ 如果只想发一条快速请求

如果你现在不想先进完整交互界面，只是想快速验证一条请求，也可以直接执行：

```bash
hermes chat -q "请用一句中文确认你已经可以正常工作"
```

![真实快速请求成功截图：在终端执行 `hermes chat -q` 后，已经返回正常中文回复，并给出会话恢复信息](../assets/rm2-3-basic-usage-02-basic-chat-flow-success.png)

现在做什么：
- 在终端执行上面的 `hermes chat -q` 命令。

为什么做这一步：
- 这能帮你用最短路径验证：Hermes 已经能收消息，也已经能正常回复。

看到什么算成功：
- 命令已经真正返回一条正常回复。
- 你能明确看出：这不是只启动了 Hermes，而是已经完成了一次最小对话。

如果没看到这个结果，先检查什么：
- 默认模型是否已经保存成功。
- 网络、鉴权、provider 是否正常。
- 你是不是把引号、命令内容输错了。

---

## 👀 进入之后你会看到什么

进入 Hermes 后，你站到的就是日常使用主界面。

在这里你最先要知道三件事：
- 你可以直接输入问题。
- 你可以继续追问，不需要每次都重新开一轮。
- 如果输入 `/`，还能继续看到更多命令入口，但这页先不展开全部斜杠命令。

现在做什么：
- 把 Hermes 当成一个正在和你持续对话的 CLI 助手，而不是一次性命令。

为什么做这一步：
- 很多新手在第一次跑通以后，还会误以为每次都要重新走安装或模型配置；其实日常使用时，你大部分时间都只是在这个主界面里工作。

看到什么算成功：
- 你已经分清“安装完成”和“日常进入 Hermes 使用”是两件不同的事。
- 你已经知道：平时真正高频使用的是交互界面本身。

如果没看到这个结果，先检查什么：
- 你是不是还把 Hermes 当成一次性安装脚本，而不是日常助手。
- 你是不是还没真正进入过交互状态。

---

## 🧪 最基础的日常使用方式

先只学会下面 4 个动作，不要一上来就把命令范围拉太大：

1. 直接输入你的问题  
2. 基于上一条回复继续追问  
3. 如果当前不想继续了，按 `Ctrl+C` 退出  
4. 如果只是想把终端画面清掉，执行 `clear`  

现在做什么：
- 先自己完整走一遍：启动 Hermes → 发一条问题 → 继续追问一次 → 退出或清屏。

为什么做这一步：
- 这一页的目标不是“学会所有命令”，而是先把最基础、最高频的日常动作跑顺。

看到什么算成功：
- 你已经能自然完成一次提问和一次追问。
- 你已经知道 `Ctrl+C` 是退出当前使用，`clear` 是清掉终端画面。
- 你不会再把最简单的日常动作和后面的高级命令混在一起。

如果没看到这个结果，先检查什么：
- 你是不是还在纠结全部 slash 命令。
- 你是不是还没有真正自己发过两轮对话。
