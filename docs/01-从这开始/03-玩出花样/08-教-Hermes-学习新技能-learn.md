# 08-教 Hermes 学习新技能（/learn）

> 💡 **速答**：`/learn` 是 Hermes 的“经验固化”入口。你先带 Agent 完成一次真实任务，确认结果可复用，再让 Hermes 把这段流程提炼成 Skill。下一次遇到同类任务时，Agent 不需要重新摸索，而是直接调用已经沉淀下来的方法。

![Hermes 自进化架构：演示、提炼、固化、复用形成闭环](../../assets/play-tricks-learn-v1.webp)

---

## 适合谁

- 已经能用 Hermes 完成日常任务，想让它越来越懂你的人。
- 经常重复处理同一类工作流的人，比如“抓网页、清洗表格、生成报告”。
- 团队里负责沉淀 SOP 的 PM、运营、研发或数据同学。
- 想把一次成功经验变成可长期复用能力的人。

---

## 你会得到什么

学完这一页，你应该能回答四个问题：

1. 什么时候适合用 `/learn`。
2. `/learn` 学到的不是聊天内容，而是可复用流程。
3. 如何用 `/journey` 检查 Agent 是否真的理解了流程。
4. 什么时候应该拒绝学习，避免把错误路径固化成 Skill。

---

## 核心原理：演示即编程

传统自动化通常要求你先写脚本、配置 YAML、定义输入输出。`/learn` 的思路相反：

1. 先做一遍真实任务。
2. 让 Agent 观察你们如何达成结果。
3. 从过程里抽出稳定步骤。
4. 生成 Skill，让未来的 Agent 可以复用。

这就是“演示即编程”。你不是先写程序，而是先完成一次正确示范。

---

## `/learn` 真正学习的是什么

`/learn` 不应该学习这些内容：

- 某一次聊天里的临时结论。
- 某个今天有效、明天就会过期的链接。
- 一次性账号、验证码、Token 或隐私信息。
- 还没验证成功的猜测。

它应该学习的是：

- 可重复的任务触发条件。
- 稳定的操作顺序。
- 常见输入和输出格式。
- 容易踩坑的检查点。
- 结果验收方式。

换句话说，它学习的是“怎么做”，不是“这次说了什么”。

---

## 实战案例：把 CSV 报表流程教给 Hermes

假设你经常收到一个销售 CSV，需要做三件事：

1. 检查字段是否齐全。
2. 清洗金额、日期、地区字段。
3. 生成一张趋势图和一份文字摘要。

你可以先正常带 Hermes 做一遍：

```text
用户：读取 ./data/sales.csv，先检查字段。
Hermes：已读取。发现字段为 date, region, product, amount。

用户：把 amount 转成数字，把 date 统一成 YYYY-MM-DD。
Hermes：已完成清洗，发现 3 行 amount 为空，已列出异常行。

用户：按月份聚合销售额，生成折线图，并写 5 条业务洞察。
Hermes：已生成 chart.png，并输出摘要。

用户：检查图表和摘要。如果没问题，把这个流程学成技能。
Hermes：建议先用 /journey 查看流程。
```

此时不要急着 `/learn`。先检查流程是否干净。

---

## 第一步：用 `/journey` 检查过程

`/journey` 的作用是让 Hermes 回放当前任务链路。你可以重点看三类信息：

```text
/journey
```

你要确认：

- 任务目标是否清楚。
- 中间步骤是否按正确顺序执行。
- 有没有把临时文件名、私人路径、一次性 Token 写进流程。
- 验收条件是否明确，比如“生成图表并检查异常行”。

如果 journey 里出现了错误步骤，先让 Hermes 修正，再学习。

---

## 第二步：触发 `/learn`

确认 journey 没问题后，再发送：

```text
/learn
```

理想情况下，Hermes 会输出类似信息：

```text
已提炼技能：csv-sales-report
触发场景：当用户要求从销售 CSV 生成趋势图和摘要时使用
核心步骤：读取字段 -> 清洗数据 -> 聚合指标 -> 生成图表 -> 输出摘要 -> 验证异常行
建议保存位置：skills/data-analysis/csv-sales-report/SKILL.md
```

这时你要看它是否做到了三件事：

1. 名字清楚。
2. 触发场景清楚。
3. 验收标准清楚。

---

## 第三步：验证 Skill 是否可复用

不要只看“已保存”。要重新开一个同类任务测试：

```text
用户：这里有一个新的 sales_2026_q2.csv，按之前的销售报表流程处理。
```

一个合格的 Skill 应该让 Hermes 主动想起：

- 先读字段。
- 再清洗日期和金额。
- 再聚合趋势。
- 最后输出图表、摘要和异常行。

如果它只记住了文件名，而没记住流程，说明学习失败，需要重写 Skill 或重新示范。

---

## 配置示例：一个好的 Skill 应该长什么样

下面是简化示例，不需要你手写，但你可以用它判断 `/learn` 的产物是否靠谱：

```markdown
---
name: csv-sales-report
description: 从销售 CSV 生成趋势图、异常行和业务摘要
---

## 触发条件
当用户提供销售 CSV，并要求生成趋势、汇总或报告时使用。

## 步骤
1. 读取 CSV 并检查字段。
2. 校验 date、region、product、amount。
3. 清洗日期和金额。
4. 汇总月度销售额。
5. 生成趋势图。
6. 输出 5 条业务洞察。
7. 列出异常行和处理建议。

## 验收标准
- 图表文件存在。
- 摘要不少于 5 条。
- 异常行没有被静默丢弃。
```

## 常见坑

### 坑 1：任务没成功就学习

如果 Agent 只是“勉强跑完”，不要 `/learn`。否则你会把错误路径固化下来。

### 坑 2：把临时信息写进 Skill

Skill 里不应该出现一次性路径、Token、验证码、个人隐私或只在当前机器有效的信息。

### 坑 3：只写步骤，不写验收

没有验收标准的 Skill 很难复用。未来 Agent 不知道做到什么程度才算完成。

### 坑 4：把偏好写成命令

用户偏好可以进入记忆，但 Skill 应该描述流程。不要把“永远这样做”写成过强指令。

---

## 什么时候不要用 `/learn`

- 任务只做一次。
- 你还没有稳定做法。
- 过程里包含大量敏感信息。
- 结果需要人工判断，暂时无法定义验收标准。
- 你只是想记录一个事实，而不是沉淀流程。

这些情况更适合用普通笔记、记忆或项目文档，而不是 Skill。

## 最小练习

你可以用下面这个小任务练手：

```text
请读取一个 Markdown 文件，提取所有二级标题，生成目录，并检查是否有重复标题。
```

完成后执行：

```text
/journey
/learn
```

然后再换一个 Markdown 文件测试是否可复用。
