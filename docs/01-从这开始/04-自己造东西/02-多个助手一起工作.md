# 👥 02-多个助手一起工作

这一页只解决一件事：
把“我一直在用同一个 Hermes”推进成“我开始按职责拆成多个完全隔离的 Hermes 助手”。

![结构图：一个人可以同时拥有多个完全隔离的 Hermes 助手，分别负责写代码、内容生产、研究分析等不同角色](../../assets/rm2-5-profiles-01-multi-profile-map.png)

---

## 🧭 先记住：这一页不是教你多开几个窗口

这一页真正要建立的心智，不是“多开几个不同名字的聊天入口”。

而是：

当你开始长期使用 Hermes，一个助手通常不该继续承接所有职责。

写代码、做内容、做研究、做运营、做 PM，这些事情如果都继续堆在同一个 Hermes 身上，最后最容易混掉的不是界面，而是：

- 人格
- 配置
- 记忆
- 会话历史
- 平台行为

所以这一页解决的不是“怎么切助手比较酷”，而是“为什么你必须开始按职责拆助手”。

---

## ❓ 为什么会需要多个助手

当你还在熟悉 Hermes 时，把大多数事情先交给一个助手，通常没有问题。
但一旦开始长期使用，你很快会碰到同一个矛盾：

- 写代码时，你想要偏工程、偏执行、偏终端的助手
- 做内容时，你想要偏表达、偏编辑、偏审稿的助手
- 做研究时，你想要偏检索、偏整理、偏分析的助手

如果这些事都继续塞给同一个助手，就容易越来越混：

- 配置想法不一样
- [`SOUL.md`](<../03-玩出花样/02-让 Hermes 更像你.md>) 想法不一样
- 记忆内容会互相污染
- 会话历史会混在一起
- [技能](../03-玩出花样/05-让工具更顺手.md)、[网关入口](../02-开始上手/05-接入一个消息平台（推荐飞书）.md)、[定时任务](<./07-让 Hermes 自己自动跑.md>)也可能开始服务不同目标

所以 Profiles 解决的不是“多开几个名字好看一点”。
而是把 Hermes 从“只有一个总助手”推进到“多个职责明确的助手系统”。

---

## ❓ Profile 是什么：它是一个完全隔离的 Hermes 环境

官方原话很明确：

> A profile is a fully isolated Hermes environment.

你可以先把它理解成：
一个 profile，不是某个聊天会话，不是某个 persona 开关，也不是临时模式；它就是一套独立的 Hermes 运行环境。

官方资料明确列出，一个 profile 会拥有自己独立的：

- `config.yaml`
- `.env`
- [`SOUL.md`](<../03-玩出花样/02-让 Hermes 更像你.md>)
- [memories](<../03-玩出花样/03-让 Hermes 记住你.md>)
- sessions
- [skills](../03-玩出花样/05-让工具更顺手.md)
- [cron jobs](<./07-让 Hermes 自己自动跑.md>)
- state database
- [gateway](../02-开始上手/05-接入一个消息平台（推荐飞书）.md)

这也是这一页最重要的判断点：
Profiles 不是“同一个助手换个昵称”，而是“另一套完整而隔离的 Hermes”。

一句话记住：
你新建的不是“第二个窗口”，而是“第二个独立助手环境”。

---

## 🎯 拆成多个助手以后，你真正会得到什么

这页最该让你看见的，不是命令本身，而是收益：

1. 一个助手只做一类事，边界更清楚
2. 长期人格不会互相打架
3. 记忆不会把不同岗位的长期事实混在一起
4. 会话历史更干净，复盘也更容易
5. 不同入口、不同平台、不同自动化任务可以有各自的承接对象

更直白一点：

你不是在“把一个助手拆碎”，而是在“把一团混合职责，拆成真正可维护的多个角色”。

## 📌 最常用的 4 种创建方式

这一页不做 profile 子命令百科。
你作为用户，先掌握最常用的 4 种创建方式就够了。

### 1）创建一个全新的空白 profile

```bash
hermes profile create mybot
```

适合什么时候：

- 你想从零开始做一个新助手
- 你不想带入当前助手的人格和配置
- 你就是想明确切开职责

### 2）复制当前 profile 的核心配置：`--clone`

```bash
hermes profile create writer --clone
```

适合：

- 你想沿用模型和 API 密钥
- 你想保留一部分人格基础
- 但你又明确希望新助手有独立历史和独立长期记忆

### 3）把当前 profile 整套状态一起复制：`--clone-all`

```bash
hermes profile create backup --clone-all
```

这更像：

- 做备份
- fork 一个已经很成熟、已经积累上下文的助手

第一次接触 Profiles 时，不要把它当默认选项。
如果你的目的是“新职责、新助手”，通常 `--clone` 更常用。

### 4）从某个指定 profile 复制，而不是从当前 profile 复制

```bash
hermes profile create work --clone --clone-from coder
```

适合：

- 你当前不在想要复制的那个 profile 里
- 你已经有一个成熟助手，想从它衍生出另一个相近角色

---

## 🔹 创建以后，平时最常用的进入 / 切换方式

创建成功后，官方最常用的进入与切换方式主要有 3 类。

### 1）直接用 profile 别名进入

例如你创建了 `coder`，就会得到：

```bash
coder chat
coder setup
coder gateway start
coder doctor
```

### 2）用 `-p` / `--profile` 显式指定目标 profile

```bash
hermes -p coder chat
hermes --profile=coder doctor
hermes chat -p coder -q "hello"
```

### 3）用 sticky default 让普通 `hermes` 命令默认打到某个 profile

```bash
hermes profile use coder
hermes chat
hermes tools
hermes profile use default
```

如果你把它理解成“切换当前默认助手”，基本就对了。

## ❓ 什么时候该建第二个助手

这部分比命令更重要。
不是所有东西都应该继续堆给一个助手。

下面这些情况，通常就该认真考虑建第二个助手了：

- 职责已经明显不同
- 你已经想让它们拥有不同人格或协作方式
- 你不希望长期记忆互相污染
- 你已经开始觉得一个助手里什么都有，反而越来越难维护

如果你脑子里已经开始出现这种表达：

- “这个更像内容助手”
- “这个更像开发助手”
- “这个应该只负责研究和检索”

那通常就已经到了该拆的时候。
