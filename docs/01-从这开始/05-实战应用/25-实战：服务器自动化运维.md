
## 标题
实战：用 Hermes Agent 实现 7x24 小时服务器自动化运维

## 适合谁
- **VPS/服务器用户**：希望服务器能自我监控、异常告警，降低夜间和节假日的心智负担。
- **懒人运维工程师**：追求“没消息就是好消息”的静默运维模式，只在出问题时接收通知。
- **Hermes Agent 进阶玩家**：想把 Agent 用在生产环境，探索 `cronjob` 和 `no_agent` 模式的真实威力。

## 目标
本文将带你用 Hermes Agent 打造一个轻量、可靠的服务器“夜班保安”。它会在后台静默巡检，只在发现磁盘占满、内存不足、网站挂掉等异常时才通过 Telegram 或企业微信向你告警。

## 正文草稿

### 巡检员 Agent 的工作逻辑

我们的目标是让 Agent 成为一个“沉默的守护者”。它的工作原则很简单：

1.  **按时巡检**：使用 `cronjob` 设置定时任务，比如每 30 分钟检查一次。
2.  **执行脚本**：运行一个专门的 Shell 脚本，检查磁盘、内存、Nginx 状态等。
3.  **判断状态**：
    *   **一切正常**：脚本不输出任何内容 (stdout 为空)。Hermes Agent 收到空输出，就认为一切安好，保持沉默。
    *   **发现异常**：脚本将格式化的告警信息输出到 stdout。Hermes Agent 收到非空内容，立即将其作为消息发送到你指定的渠道（如 Telegram）。
4.  **低资源消耗**：使用 `no_agent=True` 模式，任务不经过大模型，只执行脚本，几乎不消耗 token 和计算资源。

### ✍️ H2: 第一步：编写巡检脚本

这是我们的核心武器。创建一个 Shell 脚本，比如 `server_watchdog.sh`，存放在 Agent 能访问的路径下（例如 `~/.hermes/scripts/`）。

这个脚本负责检查你关心的指标。下面是一个简单但实用的例子：

```bash
#!/bin/bash

# --- 1. 检查磁盘空间 ---
DISK_USAGE=$(df -h / | awk 'NR==2 {print $5}' | sed 's/%//')
DISK_THRESHOLD=90 # 磁盘占用超过 90% 告警

if [ "$DISK_USAGE" -gt "$DISK_THRESHOLD" ]; then
  echo "🚨 **磁盘告警**：根分区使用率已达 ${DISK_USAGE}%，请立即清理！"
fi

# --- 2. 检查内存使用 ---
# free -m 的输出在不同系统可能不同，请自行适配
MEM_FREE=$(free -m | awk 'NR==2{printf "%.2f", $7*100/$2 }')
MEM_THRESHOLD=10 # 可用内存低于 10% 告警

# 使用 bc 进行浮点数比较
if (( $(echo "$MEM_FREE < $MEM_THRESHOLD" | bc -l) )); then
  echo "🚨 **内存告警**：可用内存仅剩 ${MEM_FREE}%，服务可能即将卡顿！"
fi

# --- 3. 检查 Nginx 服务状态 ---
# 如果你不用 Nginx，可以换成你的核心应用
if ! systemctl is-active --quiet nginx; then
  echo "🔥 **服务告警**：Nginx 服务已停止，网站无法访问！正在尝试重启..."
  # 尝试自动修复
  systemctl restart nginx
  if systemctl is-active --quiet nginx; then
    echo "✅ **自动修复**：Nginx 重启成功。"
  else
    echo "❌ **修复失败**：Nginx 重启失败，请手动干预！"
  fi
fi

# --- 4. 检查特定网站健康 ---
# 替换成你的网站地址
SITE_URL="https://your-domain.com"
HTTP_CODE=$(curl -o /dev/null -s -w "%{http_code}" --max-time 10 "$SITE_URL")

if [ "$HTTP_CODE" -ne 200 ]; then
  echo "📉 **站点告警**：访问 $SITE_URL 失败，HTTP 状态码: $HTTP_CODE。请检查网站应用！"
fi

# 如果所有检查都通过，此脚本不会有任何输出
```

**让脚本可执行**：
```sh
chmod +x ~/.hermes/scripts/server_watchdog.sh
```

### ⏰ H2: 第二步：创建 Cron Job

现在，让 Hermes Agent 定时运行这个脚本。你可以通过对话或直接使用 `hermes` CLI 创建一个 `cronjob`。

通过对话告诉 Agent：
> “创建一个 cron job，每 30 分钟运行一次 `~/.hermes/scripts/server_watchdog.sh` 脚本，使用 no_agent 模式，任务名叫‘服务器状态巡检’。”

Agent 会为你生成类似这样的任务。你也可以手动创建或通过 API 提交：

- **schedule**: `30m` (每 30 分钟)
- **script**: `~/.hermes/scripts/server_watchdog.sh`
- **no_agent**: `true`
- **deliver**: `origin` (发送到你创建任务的那个聊天窗口)
- **name**: `服务器状态巡检`

---

### ✅ H2: 第三步：验证与成功标准

如何知道它成功了？很简单：

1.  **制造一个问题**：手动停止 Nginx (`systemctl stop nginx`)。
2.  **等待告警**：在下一个 30 分钟周期，你应该会在 Telegram 收到来自 Agent 的告警，内容类似：
    > 🔥 **服务告警**：Nginx 服务已停止，网站无法访问！正在尝试重启...
    > ✅ **自动修复**：Nginx 重启成功。
3.  **解决问题**：Nginx 恢复后，脚本在下个周期又会恢复沉默。
4.  **最终标准**：你只在服务器出问题时才收到消息。平时它应该像不存在一样。

### ⚠️ H2: 常见问题与避坑

-   **脚本权限问题**：确保 `hermes` 运行用户有权限执行脚本和 `systemctl` 等命令。可能需要配置 `sudo` 免密执行。
-   **不同系统的命令差异**：`df`, `free` 等命令的输出在 CentOS, Ubuntu, aarch64 等架构上可能有细微差别，请先在你的服务器上确认命令输出并调整脚本。
-   **告警风暴**：如果一个问题持续存在（例如磁盘满了你没清理），你会每 30 分钟收到一次告警。这是设计使然，督促你解决问题。如果想实现更复杂的去重或升级逻辑，可以修改脚本或引入更专业的工具。
-   **`no_agent` vs Agent 模式**：如果你的巡检需要调用其他工具（如 `web_search`）或需要 LLM 分析日志，那就不能用 `no_agent=True`。但对于绝大多数服务器状态检查，`no_agent` 是最高效、最经济的选择。

### 🚀 H2: 下一步做什么

这个简单的“夜班保安”可以变得更强大：

-   **备份自动化**：结合我们另一篇教程 [《GitHub 备份 Cron Job》](./03-GitHub 备份 Cron Job.md)，在巡检脚本中加入备份状态检查。
-   **日志分析**：移除 `no_agent` 模式，让脚本输出关键日志，然后用 prompt 指示 LLM 分析日志中的异常模式。
-   **多节点监控**：将脚本参数化，用一份脚本监控多台服务器，并通过 `deliver` 参数将告警发送到不同的频道。
