# ⚙️ 02-认识 Hermes 的基本使用方式

你已经完成第一次互动了。现在要学的是：Hermes 平时到底怎么用。
这一页不展开高级配置，只把最基础、最高频、最容易每天重复的动作先跑顺。

---

## 🧭 先记住主入口

![真实终端主入口截图：在 Linux 终端执行 `hermes` 后，已经进入 Hermes 交互主入口并停在可继续输入的提示符位置。](../../assets/rm2-3-basic-usage-01-cli-main-surface.png)

日常最常用的入口只有一个：

```bash
hermes
```

启动后先别退出，直接在这个主界面继续问。

你现在真正要记住的不是一堆命令，而是：

以后平时要用 Hermes，先回到这个入口。

成功标准：

- 你已经进入 Hermes 的交互状态
- 终端没有停在 `command not found` 这类报错上
- 你知道以后平时要用 Hermes，就先回到这个入口

---

## ⚡ 最小使用闭环：先问一句，再追问一句

如果你刚从“跑通一次”阶段过来，最好的练习不是研究命令表，而是先完成一个最小日常闭环：

1. 进入 `hermes`
2. 问一个很简单的问题
3. 基于上一条回复继续追问一句

例如你可以这样做：

- 第一句：请用一句中文介绍你现在能帮我做什么
- 第二句：那如果我要继续上一个任务，你会怎么建议我开始

这一页真正想帮你建立的是：

Hermes 不是一次性命令，而是一个持续对话的工作入口。

---

## 🔹 快速发一条请求

如果你只想先验证一条请求，也可以直接执行：

```bash
hermes chat -q "请用一句中文确认你已经可以正常工作"
```

![真实快速请求成功截图：在终端执行 `hermes chat -q` 后，已经返回正常中文回复，并给出会话恢复信息。](../../assets/rm2-3-basic-usage-02-basic-chat-flow-success.png)

这个入口适合：

- 你只想快速验证 Hermes 现在是不是正常
- 你只想发一次请求，不想停在交互界面里
- 你想用最短方式确认模型和回复链路没问题

成功标准：

- 命令返回了一条正常回复
- 你能看出 Hermes 已经能收消息、也能正常回复
- 这不是只启动了 Hermes，而是已经完成了一次最小对话

---

## ❓ 进入后你会看到什么

进入 Hermes 后，你站到的就是日常使用主界面。

先记住三件事：

- 你可以直接输入问题
- 你可以基于上一条回复继续追问
- 输入 `/` 时还能看到更多命令入口，但这一页先不展开全部斜杠命令

这页只要你先把它当成一个持续对话的 CLI 助手，而不是一次性命令，就算理解到位了。

---

## 📌 最基础的 4 个动作

先只学会下面 4 个动作：

1. 直接输入问题
2. 基于上一条回复继续追问
3. 按 `Ctrl+C` 退出当前会话
4. 执行 `clear` 清掉终端画面

这里最容易混淆的是：

- `Ctrl+C`：结束当前使用
- `clear`：只是把终端画面清干净

它们不是一回事。

成功标准：

- 你已经能自然完成一次提问和一次追问
- 你已经知道 `Ctrl+C` 是退出当前使用，`clear` 是清屏
- 你不会把最简单的日常动作和后面的高级命令混在一起
