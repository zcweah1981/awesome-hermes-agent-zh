# 02-安装 / 更新 / 环境问题

> 🎯 一句话结论：如果你现在卡在 `hermes` 命令根本跑不起来、安装脚本半路失败、更新后命令异常，或者把 Windows / WSL2 / shell / PATH 混在了一起，这一页先帮你把“环境层”问题拆开，不要一上来就删目录重装。

这一页只解决一件事：把 **安装前提、安装命令、shell 生效、更新后异常、Windows / WSL2 环境混用** 这几类最常见问题先排顺。

## 🧭 先判断：你更像卡在哪一种

| 你现在的现象 | 更像是哪一类问题 | 先做什么 |
|---|---|---|
| `hermes: command not found` | shell / PATH 没生效 | 先重新加载 shell，再查 `~/.local/bin` |
| 一键安装脚本一开始就失败 | 网络 / Git / 终端环境不对 | 先确认 Git、终端类型、网络 |
| Windows 里直接跑，行为很怪 | 原生 Windows 路径误用 | 先切回 WSL2，再安装 |
| 更新后原本可用，现在命令异常 | 版本更新后 shell / venv / PATH 未刷新 | 先重开终端，再跑 `hermes version` / `hermes doctor` |
| `hermes` 能运行，但后面 provider / model 才报错 | 这已经不是纯安装层 | 先去看模型 / Provider 问题页 |

如果你现在还没分清，先执行下面这 3 个命令：

```bash
which hermes
hermes version
hermes doctor
```

这三条的作用不是“修复”，而是先判断问题还停留在环境层，还是已经进入 Hermes 本体层。

## 📚 官方基线先记住

根据 Hermes 官方 Installation / Quickstart / FAQ，安装层最关键的几条基线是：

- 官方推荐的一键安装路径只支持 **Linux / macOS / WSL2**
- **Native Windows 不支持**，Windows 用户要先进 **WSL2**
- 一键安装命令是：

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

- 安装完成后，通常还要 **重新加载 shell**
- 如果 `hermes` 命令都还没生效，不要先查模型、Gateway、MCP

## ✅ 最稳的排查顺序

安装 / 更新 / 环境问题，先按这个顺序查：

1. 先确认你是不是在正确环境里
2. 再确认安装命令有没有完整执行
3. 再确认 shell / PATH 有没有生效
4. 再确认更新后是不是只差重开终端或重新加载 shell
5. 最后才决定要不要手动安装或重装

这样排的原因很简单：

- 大多数“安装失败”其实不是 Hermes 逻辑坏了，而是环境层没对齐
- 大多数“更新后坏了”其实不是代码全坏，而是新命令路径还没进当前 shell
- 一上来就删目录重装，通常会把原本可定位的问题变成更乱的混合问题

## 1）先确认你是不是在正确终端里

现在做什么：
- 先确认你当前终端到底是不是官方支持环境

为什么先做：
- 如果环境本身就不在官方支持范围里，后面的报错参考价值很低

你现在应该对照这条基线：

- macOS：可以
- Linux：可以
- WSL2：可以
- Native Windows：不行

如果你是 Windows 用户，先不要在 PowerShell / CMD 里硬跑安装链路。
正确动作是：

- 先装 WSL2
- 打开 WSL2 里的 Linux 终端
- 再在 WSL2 里执行官方安装命令

看到什么算成功：
- 你能明确回答“我现在是在 Linux / macOS / WSL2 里，不是在 Native Windows 里硬跑”

如果没成功先查什么：
- 回 [01-从这开始 / 02-先准备运行环境](../01-从这开始/01-先跑起来/02-先准备运行环境.md)
- 回官方 WSL2 安装说明：<https://learn.microsoft.com/en-us/windows/wsl/install>

## 2）确认安装命令和 Git 都没问题

现在做什么：
- 先确认 Git 可用，再确认你执行的是官方安装命令

为什么先做：
- 官方安装链路把 Git 当成基础前提之一
- 命令少字、漏管道、网络半断，都会让你误以为是 Hermes 自己安装坏了

先执行：

```bash
git --version
```

再执行官方安装命令：

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

看到什么算成功：
- `git --version` 能正常返回版本号
- 安装器开始执行，而不是在命令刚输入时就直接报错

如果没成功先查什么：
- Git 是否缺失
- 网络 / 代理是否影响 GitHub 脚本下载
- 你是否在受限终端、公司跳板或错误 shell 里执行

## 3）如果提示 `hermes: command not found`

这是安装页最常见的一类问题。

先不要急着重装，先按官方 FAQ 的顺序查：

### 先做什么
先重新加载当前 shell：

```bash
source ~/.bashrc
```

如果你用的是 zsh：

```bash
source ~/.zshrc
```

然后检查：

```bash
which hermes
ls ~/.local/bin/hermes
```

### 为什么这样查
因为这类报错最常见的根因不是“没装上”，而是：

- 新 PATH 还没进入当前终端会话
- 你安装完还在旧 shell 里
- `~/.local/bin` 还没生效

### 如果还是不行
可以临时手动把路径加进去再测：

```bash
export PATH="$HOME/.local/bin:$PATH"
```

然后重新执行：

```bash
hermes version
```

### 看到什么算成功
- `which hermes` 能返回实际路径
- `hermes version` 能正常输出版本

## 4）更新后变怪，先查这 4 件事

如果你是“之前能用，更新后变异常”，先不要自动判断成 Hermes 新版本坏了。

先查：

1. 你是不是还在旧终端会话里
2. shell 有没有重新加载
3. `which hermes` 指向的是不是你预期的路径
4. `hermes doctor` 有没有给出更具体的环境提示

推荐你按这个最小动作顺序做：

```bash
which hermes
hermes version
hermes doctor
```

如果这三步里：

- `which hermes` 就不对
  - 先修 PATH / shell
- `hermes version` 正常，但 `hermes doctor` 异常
  - 说明已不只是 PATH，而是进入 Hermes 运行层
- 两个都正常
  - 那你现在更可能卡在模型、CLI / TUI、Gateway 或工具层，不该继续停在安装页

## 5）这些现象，不要误判成“必须重装”

下面几类问题很常见，但都不该一上来就删目录重装：

- 安装完只是没 reload shell
- Windows 用户跑错到了 PowerShell / CMD
- PATH 里没有 `~/.local/bin`
- 更新后旧终端没关
- provider / model 报错被误判成安装失败

更稳的判断标准是：

- 只要 `hermes version` 和 `hermes doctor` 还能给出有效输出，就先不要把它当成“完全没装成”

## 6）什么时候才考虑手动安装

只有在下面这些情况，你才更应该去看官方 Installation 页里的手动安装部分：

- 一键安装路径反复失败
- 你明确需要手动控制 Python / uv / extras
- 你在特殊环境里要自己装依赖
- 你已经确认不是 shell / PATH / 终端类型问题

这时再回官方 Installation：

- <https://hermes-agent.nousresearch.com/docs/getting-started/installation>

如果你只是想先把 Hermes 跑起来，不要先跳进手动安装，把复杂度抬高。

## 🇨🇳 中国环境里最常见的额外误区

如果你在中文环境里落地，下面这些问题经常会伪装成“安装失败”：

- GitHub 脚本下载慢或失败
- 代理规则只管浏览器，不管终端
- 服务器 / 云主机本身缺 Git
- WSL2 和 Windows 路径混用
- 装完以后直接切去折腾 Gateway / provider，没先验证基础命令

所以中国环境里更稳的原则是：

- 先把“终端环境 + Git + 安装器 + shell 生效”这 4 层单独跑通
- 再进入模型、入口和工具层
