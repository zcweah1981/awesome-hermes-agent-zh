# 02-安装 / 更新 / 环境问题

> 🎯 一句话结论：这一页不是带你从头安装 Hermes，而是集中回答“为什么装不上、为什么更新后变怪、为什么命令突然找不到”这类最常见的安装 / 更新 / 环境问题。

如果你现在最焦虑，只先记住一句：

> 只要还没分清是环境层、PATH 层，还是 Hermes 本体层问题，就不要急着删目录重装。

## 这页主要回答什么

这一页集中回答这几类高频问题：

- 为什么 `hermes` 命令找不到？
- 为什么安装脚本一开始就失败？
- 为什么 Windows 上装起来总是不对？
- 为什么更新之后原本可用，现在突然异常？
- 什么情况下该继续排环境，什么情况下该转去查 [03-模型 / Provider / 自定义 endpoint 问题](<./03-模型 Provider 与自定义 endpoint 问题.md>)？

## 先做一个最小判断

如果你现在完全不知道问题卡在哪，先跑这 3 条：

```bash
which hermes
hermes version
hermes doctor
```

这 3 条的作用不是立刻修好，而是先帮你判断：

- 还是环境层问题
- 还是 PATH / shell 没生效
- 还是已经进入 Hermes 本体、[Provider / 模型层](<./03-模型 Provider 与自定义 endpoint 问题.md>)的问题

## ❓FAQ 正文

<a id="faq-command-not-found"></a>

### 🚫 01｜为什么我一执行就提示 `hermes: command not found`？

> ❓ 问题：为什么我一执行就提示 `hermes: command not found`？
>
> 💡 先说结论：最常见原因不是“完全没装上”，而是 shell / PATH 还没生效。

最常见原因是：

- shell 还没重新加载
- 你还在旧终端会话里
- `~/.local/bin` 还没进入当前 PATH

🔎 先做什么：

```bash
source ~/.bashrc
```

如果你用的是 zsh：

```bash
source ~/.zshrc
```

然后再检查：

```bash
which hermes
ls ~/.local/bin/hermes
```

如果还是不行，可以临时补 PATH：

```bash
export PATH="$HOME/.local/bin:$PATH"
```

再重新执行：

```bash
hermes version
```

🚦 什么时候该跳转：

- 如果 `hermes version` 仍然完全跑不起来，继续留在本页排环境
- 如果 `hermes version` 已经正常、只是模型或接口报错，转去下一页查 [03-模型 / Provider / 自定义 endpoint 问题](<./03-模型 Provider 与自定义 endpoint 问题.md>)

---

<a id="faq-install-script-fails"></a>

### 🚫 02｜为什么安装脚本一开始就失败？

> ❓ 问题：为什么安装脚本一开始就失败？
>
> 💡 先说结论：这类问题先不要怀疑 Hermes 本体，先查命令、网络、Git。

这类问题通常先查 3 件事：

1. 你执行的是不是官方完整命令
2. 当前网络 / 代理是否能正常拉取 GitHub 脚本
3. Git 是否已可用

🔎 先做什么：

官方一键安装命令是：

```bash
curl -fsSL https://raw.githubusercontent.com/NousResearch/hermes-agent/main/scripts/install.sh | bash
```

Git 基础检查：

```bash
git --version
```

如果 `git --version` 都不正常，先修 Git，不要先怀疑 Hermes 自己坏了。

🚦 什么时候该跳转：

- 如果 `git --version` 都不正常，先修 Git
- 如果 Git 正常、安装器也能启动，但后面卡在模型配置，就不要继续停留在安装页，直接转去 [03-模型 / Provider / 自定义 endpoint 问题](<./03-模型 Provider 与自定义 endpoint 问题.md>)

<a id="faq-windows-wsl"></a>

### 🪟 03｜Windows 为什么总装不对？

> ❓ 问题：Windows 为什么总装不对？
>
> 💡 先说结论：因为 Hermes 官方不支持 Native Windows，Windows 用户要先切到 WSL2。

因为 Hermes 官方基线很明确：

- 支持：Linux / macOS / WSL2
- **不支持：Native Windows**

也就是说，如果你在 PowerShell / CMD 里直接走官方安装链路，很多异常都不值得继续深挖。

🔎 先做什么：

- 先安装 WSL2
- 打开 WSL2 里的 Linux 终端
- 再在 WSL2 里执行官方安装命令

如果你现在还在 Native Windows 里硬装，这一页先给你的结论不是“继续排细节”，而是：

- 先切回 WSL2

🚦 什么时候该跳转：

- 如果你还在 PowerShell / CMD 里，先不要继续排细节
- 如果你已经在 WSL2 里，再回到本页继续查安装命令和 shell；如果你其实还没把基础安装主线走顺，也可以先回到 [01-先跑起来 / 04-把 Hermes 装上去](<../01-从这开始/01-先跑起来/04-把 Hermes 装上去.md>)

<a id="faq-update-broken"></a>

### 🔄 04｜更新之后突然变怪，是不是新版本坏了？

> ❓ 问题：更新之后突然变怪，是不是新版本坏了？
>
> 💡 先说结论：不一定，很多时候只是旧终端没关、shell 没 reload，或者问题已经转到配置 / 模型层。

更新后异常，最常见的几种情况是：

- 你还在旧终端会话里
- shell 没重新加载
- `which hermes` 指向的路径不是你预期的那份
- 其实不是安装层，而是 provider / model / config 层开始报错

🔎 先做什么：

最小排查顺序：

```bash
which hermes
hermes version
hermes doctor
```

如果：

- `which hermes` 不对 → 先修 PATH / shell
- `hermes version` 正常、`hermes doctor` 异常 → 说明已经不只是环境层
- 两个都正常 → 你更该去查 [03-模型 / Provider / 自定义 endpoint 问题](<./03-模型 Provider 与自定义 endpoint 问题.md>)、[04-CLI / TUI / 会话问题](<./04-CLI TUI 与会话问题.md>)、[05-Gateway / Messaging / 推送问题](<./05-Gateway Messaging 与推送问题.md>) 或 [06-Tools / Skills / MCP 问题](<./06-Tools Skills MCP 问题.md>)

🚦 什么时候该跳转：

- `which hermes` 不对：继续留在本页查 PATH / shell
- `hermes doctor` 开始报 provider / model：转去下一页

<a id="faq-dont-reinstall"></a>

### 🔄 05｜什么情况先不要重装？

> ❓ 问题：什么情况先不要重装？
>
> 💡 先说结论：只要基础命令还能给出有效输出，就先不要把它判成“必须重装”。

下面这些情况都不建议一上来就删目录重装：

- 安装完只是没 reload shell
- Windows 用户其实跑错到了 PowerShell / CMD
- PATH 里没有 `~/.local/bin`
- 更新后只是旧终端没关
- 真正报错点其实在 provider / model，而不是安装

🔎 先做什么：

更稳的判断标准是：

- 只要 `hermes version` 和 `hermes doctor` 还能给出有效输出，就先不要把它判成“完全没装成”

<a id="faq-manual-install"></a>

### 🔄 06｜什么情况才该看手动安装？

> ❓ 问题：什么情况才该看手动安装？
>
> 💡 先说结论：只有在一键安装反复失败、而且你已经确认不是环境 / shell / PATH 问题时，才值得转手动安装。

只有在下面这些情况，你才更应该转去官方 Installation 页里的手动安装部分：

- 一键安装路径反复失败
- 你明确要手动控制 Python / uv / extras
- 你所在环境比较特殊，需要自己装依赖
- 你已经确认不是 shell / PATH / 终端类型问题

🔎 先做什么：

- 先把一键安装链路跑完
- 先确认 Git、终端、PATH、shell 都没问题
- 再决定要不要进手动安装

<a id="faq-install-vs-model"></a>

### 🧭 07｜我怎么判断现在还是“安装层问题”，还是已经进入“模型层问题”？

> ❓ 问题：我怎么判断现在还是“安装层问题”，还是已经进入“模型层问题”？
>
> 💡 先说结论：能不能正常跑 `hermes version` / `hermes doctor`，就是最实用的分界线。

一个很实用的分界线是：

- 如果 `hermes` 命令本身都起不来，优先还是安装 / 环境层
- 如果 `hermes version` 正常、`hermes doctor` 也能跑，只是在选模型、API Key、endpoint 时出错，那已经更像模型 / Provider 问题

🔎 先做什么：

也就是说：

- 环境层关心的是“命令有没有真正生效”
- 模型层关心的是“命令生效后，为什么推理链路不通”

<a id="faq-china-env"></a>

### 🧭 08｜中国环境里最容易伪装成“安装失败”的是什么？

> ❓ 问题：中国环境里最容易伪装成“安装失败”的是什么？
>
> 💡 先说结论：最常见的伪装项不是 Hermes 自己坏了，而是 GitHub 下载、终端代理、WSL2/Windows 混用这些环境问题。

在中文环境里，最常见的伪装项有：

- GitHub 脚本下载慢或失败
- 代理只管浏览器，不管终端
- 云主机本身缺 Git
- WSL2 和 Windows 路径混用
- 装完以后直接跳去折腾 [Gateway](<./05-Gateway Messaging 与推送问题.md>) / [Provider](<./03-模型 Provider 与自定义 endpoint 问题.md>)，没有先验证基础命令

🔎 先做什么：

所以在中国环境里更稳的原则是：

- 先把“终端环境 + Git + 安装器 + shell 生效”这 4 层单独跑通
- 再进入[模型层](<./03-模型 Provider 与自定义 endpoint 问题.md>)、[入口层](<./05-Gateway Messaging 与推送问题.md>)和[工具层](<./06-Tools Skills MCP 问题.md>)

<a id="faq-installer-stuck"></a>

### 🧭 09｜如果官方安装器卡在依赖安装提示怎么办？

> ❓ 问题：如果官方安装器卡在依赖安装提示怎么办？
>
> 💡 先说结论：如果你是在 Windows 场景里卡住，先不要乱改命令，优先切回 WSL 终端再执行。

官方 issue 里已经有一个很典型的 Windows 相关案例：

- 安装器卡在依赖安装提示时，实际修法不是乱改命令
- 而是切回 **WSL 终端** 再执行安装

所以如果你是在 Windows 场景里遇到这类交互卡住，先不要继续在错误终端里硬试。
