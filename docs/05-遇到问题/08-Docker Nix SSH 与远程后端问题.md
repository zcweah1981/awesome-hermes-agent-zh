# 08-Docker / Nix / SSH / 远程后端问题

> 🎯 一句话结论：这一页不是教你重新配一遍 Docker、SSH 或远程 backend，而是集中回答“为什么容器里起不来、为什么 SSH backend 连不上、为什么远端文件和本地感受不一致、为什么我以为在一台机器上，实际跑在另一台”这类高频问题。

如果你现在最焦虑，只先记住一句：

> Docker / Nix / SSH / 远程后端问题最常见不是 Hermes 核心逻辑坏了，而是你对“它到底跑在哪、谁在执行、谁在读文件、谁在持有环境”的边界理解错了。

## 这页主要回答什么

这一页集中回答这几类高频问题：

- 为什么 Docker backend 起不来？
- 为什么 SSH backend 连不上或行为不对？
- 为什么远端文件、依赖、路径和我本地理解的不一样？
- 为什么我明明改了本地文件，远端执行看起来没变化？
- 什么情况下该把问题归到远端 backend，而不是 CLI / 模型 / 配置？

## 先做一个最小判断

如果你现在完全不知道问题卡在哪，先问自己这 4 个问题：

1. 我现在到底是在本地执行，还是在 Docker / SSH / 远端 backend 执行？
2. 当前真正读文件、跑命令的是哪台机器 / 哪个环境？
3. 我看到的问题是“连不上”，还是“连上了但环境不对”？
4. 我改的文件和它实际读取的文件，是不是同一份？

很多远端 backend 问题，只要先把这 4 个问题分开，基本就不会继续盲改。

## ❓FAQ 正文

<a id="faq-docker-not-starting"></a>

### 🐳 01｜为什么 Docker backend 起不来？

> ❓ 问题：为什么 Docker backend 起不来？
>
> 💡 先说结论：最常见原因不是 Hermes agent 坏了，而是 Docker backend 所需的运行条件、镜像环境或当前 backend 配置根本没对齐。

最常见原因是：

- Docker backend 根本没正确配置到当前环境
- 容器运行条件不满足
- 你以为当前真的在用 Docker backend，实际不是
- 问题其实不在 Hermes，而在 Docker 环境本身

🔎 先做什么：

先不要急着怀疑 agent 推理链路。
先问：

- 当前 backend 到底是不是 docker
- 当前命令到底在本地执行，还是应该进容器执行
- 这是不是 backend 选择问题，而不是模型问题

🚦 什么时候该跳转：

- 如果你连当前 backend 是谁都没分清，先留在本页
- 如果问题其实是 `config.yaml` / backend 选择错了，后续更该去 [07-配置 / Profiles / 环境隔离问题](<./07-配置 Profiles 与环境隔离问题.md>)

---

<a id="faq-docker-local-confusion"></a>

### 🐳 02｜为什么我以为进了容器，但行为还是像本地？

> ❓ 问题：为什么我以为进了容器，但行为还是像本地？
>
> 💡 先说结论：最常见原因不是容器“半坏”，而是你把“配置成 docker backend”与“当前所有动作都已经在容器里跑”当成同一件事了。

最常见混淆是：

- 你改了 backend，但当前入口还没真正切过去
- 你在看本地文件，却以为容器也会同步看到
- 你把“命令发出地”和“命令执行地”混成了一件事

🔎 先做什么：

先问：

- 当前实际执行是在本地，还是在容器里
- 当前读文件的是哪边
- 我看到的是本地状态，还是 backend 状态

🚦 什么时候该跳转：

- 如果核心问题是“哪套配置在生效”，回 [07-配置 / Profiles / 环境隔离问题](<./07-配置 Profiles 与环境隔离问题.md>)
- 如果核心问题是“容器环境本身不对”，留在本页

<a id="faq-ssh-not-connecting"></a>

### 🔐 03｜为什么 SSH backend 连不上？

> ❓ 问题：为什么 SSH backend 连不上？
>
> 💡 先说结论：最常见原因不是 Hermes 不支持 SSH，而是 SSH 目标、认证、网络可达性、远端可执行环境或 backend 配置并没有真正对齐。

最常见原因是：

- 远端主机本身不可达
- SSH 认证没通
- 你写的远端 backend 信息不对
- 远端虽然能连，但不具备 Hermes 预期环境

🔎 先做什么：

先不要先查 provider / model。
先确认：

- 这台远端主机是不是本来就能 SSH 连接
- 你当前 backend 确实在指向这台机器
- 问题是“完全连不上”，还是“连上后环境不对”

🚦 什么时候该跳转：

- 如果问题就是 SSH 层，留在本页
- 如果 SSH 已经通了，但远端环境配置错，后续更该去 [07-配置 / Profiles / 环境隔离问题](<./07-配置 Profiles 与环境隔离问题.md>) 或 [03-国内落地 / 01-总览](../03-国内落地/01-总览.md)

<a id="faq-ssh-wrong-env"></a>

### 🔐 04｜为什么 SSH 看起来连上了，但执行环境还是不对？

> ❓ 问题：为什么 SSH 看起来连上了，但执行环境还是不对？
>
> 💡 先说结论：因为“SSH 连上了”只证明通道建立了，不等于远端那台机器上的路径、依赖、工作目录、配置文件、profile 都和你本地预期一致。

最常见误判是：

- 以为 SSH 通了就等于一切都对
- 以为远端会自动拥有和本地相同的依赖
- 以为本地改的配置文件远端会自动同步

🔎 先做什么：

先把“连接成功”和“环境正确”分开。
然后问：

- 远端机器上到底有什么
- 远端机器现在读的是哪套配置
- 远端路径、依赖、shell 环境是否真的已准备好

🚦 什么时候该跳转：

- 如果你发现问题已经是远端机器准备不足，回 [03-国内落地 / 01-总览](../03-国内落地/01-总览.md) / [04-自己造东西](../01-从这开始/04-自己造东西/01-总览.md)
- 如果仍然是 backend 行为边界不清，留在本页

<a id="faq-remote-files-different"></a>

### 📁 05｜为什么远端文件、路径、依赖和我本地理解的不一样？

> ❓ 问题：为什么远端文件、路径、依赖和我本地理解的不一样？
>
> 💡 先说结论：因为远端 backend 最常见的问题，就是你脑子里默认“它和本地一样”，但实际上它本来就不是本地那套文件系统和依赖环境。

最常见原因是：

- 远端 backend 读的是远端文件系统
- 本地路径在远端根本不存在
- 本地装过的依赖，远端没装
- 你把“我的项目目录”理解成对远端也自动成立

🔎 先做什么：

先放弃“本地当然等于远端”的默认假设。
先确认：

- 远端当前工作目录到底是什么
- 远端机器上项目是否真的在那个位置
- 远端依赖是否真的存在

🚦 什么时候该跳转：

- 如果你本质上是在查“这台机器怎么部署 / 准备环境”，回 [03-国内落地 / 01-总览](../03-国内落地/01-总览.md)
- 如果你是在查 backend 边界理解，留在本页

<a id="faq-local-change-no-effect"></a>

### 📁 06｜为什么我改了本地文件，远端执行看起来没变化？

> ❓ 问题：为什么我改了本地文件，远端执行看起来没变化？
>
> 💡 先说结论：最常见原因不是 Hermes 缓存了旧结果，而是你改的是本地文件，但远端执行根本不读这份本地文件。

这是远端 backend 场景里最常见的错觉之一。

最常见原因是：

- 本地改动没有进入远端环境
- 远端实际跑的是另一份代码 / 文件
- 你把“本机编辑器看到的文件”误当成“远端正在执行的文件”

🔎 先做什么：

先问：

- 当前执行地到底在哪
- 当前读取的是哪份文件
- 我改完以后，这个改动有没有进入远端运行环境

🚦 什么时候该跳转：

- 如果根因更像“部署 / 同步链路没建立”，回部署相关页
- 如果只是远端 backend 的文件边界没分清，留在本页

<a id="faq-missing-deps"></a>

### 📁 07｜为什么容器 / 远端里找不到我以为已经有的依赖？

> ❓ 问题：为什么容器 / 远端里找不到我以为已经有的依赖？
>
> 💡 先说结论：因为“我本地装过”不等于“容器里也装过”，更不等于“远端主机也装过”。

这类问题最常见的根因非常朴素：

- 依赖只在本机
- 容器里没有
- 远端机器也没有

一旦你进入 Docker / SSH / 远端 backend，依赖问题就一定要按“执行环境是谁”来判断。

🔎 先做什么：

先把问题拆开：

1. 依赖在哪台机器 / 哪个环境里
2. 当前命令到底在哪个环境执行
3. 我是不是把“本机已安装”误读成“所有 backend 已安装”

🚦 什么时候该跳转：

- 如果你已经确定是环境准备不足，回 [03-国内落地 / 01-总览](../03-国内落地/01-总览.md) 或 [02-安装 / 更新 / 环境问题](./02-安装更新与环境问题.md)
- 如果你还在分不清执行环境是谁，继续留在本页

<a id="faq-backend-vs-cli"></a>

### 🧭 08｜什么时候该把问题归到远端 backend，而不是 CLI / 模型？

> ❓ 问题：什么时候该把问题归到远端 backend，而不是 CLI / 模型？
>
> 💡 先说结论：如果问题主要体现在“跑在哪、读哪份文件、用哪套依赖、连哪台机器”，更像 backend；如果问题主要体现在“会不会回、模型认不认、provider 报什么错”，更像 CLI / 模型层。

一个很实用的分界线是：

- backend 层关心的是“执行环境边界”
- CLI 层关心的是“交互方式”
- 模型层关心的是“推理链路”

🔎 先做什么：

先问自己：

1. 我的问题发生在“发送前”，还是“执行中”？
2. 我的问题是“连不上某环境”，还是“环境里结果不对”？
3. 我的问题是“谁在执行”，还是“执行完返回什么”？

🚦 什么时候该跳转：

- 如果是 provider / model 报错，回 [03-模型 / Provider / 自定义 endpoint 问题](<./03-模型 Provider 与自定义 endpoint 问题.md>)
- 如果是交互体验异常，回 [04-CLI / TUI / 会话问题](<./04-CLI TUI 与会话问题.md>)
- 如果是执行环境边界问题，留在本页

<a id="faq-back-to-config-deploy"></a>

### 🧭 09｜什么时候该回配置 / 部署页，而不是继续在这里硬调？

> ❓ 问题：什么时候该回配置 / 部署页，而不是继续在这里硬调？
>
> 💡 先说结论：只要你现在的问题已经不是“backend 行为哪里怪”，而是“这台环境到底怎么准备、怎么部署、怎么选路线”，就不该继续把它当单点 backend 问题硬调。

更适合回配置 / 部署页的情况是：

- 你还没分清本地、容器、远端主机三条路
- 你现在其实是在补环境基础设施
- 你现在更像在搭运行环境，而不是排 Hermes backend 单点问题

🔎 先做什么：

先回到：

- 安装 / 更新 / 环境问题
- 国内落地 / 部署总览
- 配置 / Profiles / 环境隔离问题

把环境边界重新整理完，再回来调 backend。

🚦 什么时候该跳转：

- 回 [02-安装 / 更新 / 环境问题](./02-安装更新与环境问题.md)
- 回 [07-配置 / Profiles / 环境隔离问题](<./07-配置 Profiles 与环境隔离问题.md>)
