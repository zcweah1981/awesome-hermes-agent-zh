## 🚀 1. 性能：首 token 响应提速 80%

v0.19.0 重新实现了 Agent Loop 的初始化路径，首 token 时间从 **4.3 秒降到 0.9 秒**（中位数，基于官方 benchmark）。

**对你意味着什么**：
- 对话体感从"等一下"变成"秒回"
- Cron 任务和 Gateway 消息的响应延迟显著缩短
- 多 Agent 编排（Kanban / MoA）的并行启动更快

**不需要你做什么**：这是内部优化，升级后自动生效。

---

## 🤖 2. 智能审批成为默认（行为变更）

v0.18.x 及之前：标记为需要审批的命令（如 `execute_command`、`file_write`）每次执行都需要用户手动确认。

v0.19.0：引入 **LLM 审查器**（Approval LLM），自动评估命令安全性。安全的命令自动放行，仅高风险操作才弹审批。

**配置方式**：

```yaml
# ~/.hermes/profiles/default/config.yaml
agent:
  approval:
    mode: smart          # smart（默认）| manual | off
    llm_provider: openai  # 用哪个 provider 做审查
    llm_model: gpt-4o-mini  # 审查模型（建议用快模型省钱）
```

| 模式 | 行为 | 适合场景 |
|------|------|---------|
| `smart` | LLM 审查器自动评估，低风险放行、高风险弹审批 | 日常使用（新默认） |
| `manual` | 每次标记命令都手动确认 | 安全敏感环境 |
| `off` | 不做审批 | 完全信任的自动化场景 |

**回退到旧行为**：如果你不信任自动审批，升级后把 `mode` 改成 `manual` 即可恢复 v0.18.x 的体验。

## 🔐 3. Bitwarden / 1Password 密码管理器集成

v0.19.0 新增 `SecretSource` 接口，API 密钥不再必须明文写在 `.env` 或 `config.yaml` 里。

**支持的密码管理器**：

| 密码管理器 | 配置方式 |
|------------|---------|
| Bitwarden | `secret_source: bitwarden` |
| 1Password | `secret_source: 1password` |

**配置示例**：

```yaml
# ~/.hermes/profiles/default/config.yaml
providers:
  openai:
    api_key:
      secret_source: bitwarden
      item: "Hermes OpenAI Key"
      field: "password"
```

**对你意味着什么**：
- API 密钥轮换不再需要改 Hermes 配置
- 团队共享 profile 时不会泄露密钥
- 符合企业安全合规要求

## 🧬 4. Profile 多路复用路由

v0.19.0 支持一个 Gateway（如 Telegram Bot token）或一个 Bot 入口路由到多个隔离的 profile。

**配置示例**：

```yaml
# ~/.hermes/gateways/telegram.yaml
gateway: telegram
bot_token: "your-bot-token"
profile_routing:
  - match: "/analyst"
    profile: analyst
  - match: "/coder"
    profile: coder
  - default: true
    profile: default
```

**对你意味着什么**：
- 不用为每个角色部署单独的 Hermes 实例
- 一个 Telegram Bot 可以按命令前缀切换到不同 Agent 人格
- 不同 profile 的 memory、skills、tools 完全隔离

## 📤 5. 后台子代理 + 持久化交付账本

v0.19.0 的 `delegate_task` 工具新增 `background: true` 参数，子代理可以在后台异步执行任务。

**核心机制**：
- 后台子代理的执行状态写入**持久化交付账本**（Persistent Delivery Ledger）
- 如果 Hermes 崩溃或重启，未完成的子代理任务会在重启后自动恢复
- 子代理完成后，结果通过通知机制推送给主代理

**使用示例**：

```python
# 在对话中委派后台任务
delegate_task(
    description="分析这个仓库的代码质量并生成报告",
    background=True,  # v0.19.0 新增
    notify_on_complete=True
)
```

**对你意味着什么**：
- 长时间运行的分析任务不再阻塞主对话
- 崩溃恢复后不会丢失子代理进度
- 适合 Kanban 多 Agent 编排场景

```bash
# 或通过 setup 向导
hermes setup model
```

## 🎛 7. 推理强度 max / ultra

v0.19.0 将推理深度从"开关"升级为"旋钮"——支持 `low` / `medium` / `high` / `max` / `ultra` 五档。

**配置方式**：

```yaml
# ~/.hermes/profiles/default/config.yaml
agent:
  reasoning_effort: high  # low | medium | high | max | ultra
```

| 档位 | 适合场景 | Token 成本 |
|------|---------|-----------|
| `low` | 简单问答、闲聊 | 最低 |
| `medium` | 日常任务（旧默认） | 中等 |
| `high` | 代码生成、分析任务 | 较高 |
| `max` | 复杂推理、架构设计 | 高 |
| `ultra` | 极限推理、竞赛级问题 | 最高 |

**在对话中临时切换**：

```
/model gpt-5.6 --reasoning max
```

## 💾 8. 会话导出

v0.19.0 新增 `hermes sessions export` 命令，支持将历史会话导出为多种格式。

```bash
# 导出为 Markdown
hermes sessions export --format markdown --output ./session.md

# 导出为 HTML（带样式）
hermes sessions export --format html --output ./session.html

# 导出为 HuggingFace trace（用于训练数据）
hermes sessions export --format hf-trace --output ./trace.jsonl

# 导出最近 7 天所有会话
hermes sessions export --format markdown --since 7d --output ./recent/
```

**对你意味着什么**：
- 会话归档和审计更方便
- 可以把成功的工作流导出为训练数据
- HTML 导出适合分享给非技术用户查看

## ❓ 常见问题

### v0.19.0 的智能审批安全吗？

智能审批使用独立的 LLM 审查器评估每个命令的安全性。审查器会分析命令内容、文件路径、网络请求等因素。对于不确定的命令，仍然会弹出人工审批。如果你在安全敏感环境使用，可以把 `mode` 设为 `manual` 恢复旧行为。

### 升级到 v0.19.0 后旧的配置还兼容吗？

兼容。v0.19.0 的配置迁移工具会自动处理大部分变更。升级后跑 `hermes config migrate` 即可。新增字段（如 `approval.mode`）有默认值，不需要手动添加。

### Bitwarden / 1Password 集成需要额外安装什么吗？

需要安装对应密码管理器的 CLI 工具：
- Bitwarden: `npm install -g @bitwarden/cli`
- 1Password: 下载 [1Password CLI](https://developer.1password.com/docs/cli/)

安装后先登录一次，Hermes 会通过 CLI 读取密钥。

### Profile 多路复用和原来多实例部署有什么区别？

多路复用是**一个 Hermes 进程**内运行多个隔离 profile，共享 Agent Loop 但 memory / skills / tools 独立。多实例部署是多个独立进程，完全隔离但资源消耗更大。多路复用适合轻量场景（一个 Bot 多人格），多实例适合安全隔离要求高的场景。
