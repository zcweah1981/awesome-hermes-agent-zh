# 01-总览｜Reference 参考手册

> 🎯 一句话结论：Reference 模块不是教程，也不是排障页，而是 Hermes 官方 Reference 的中文查表入口。你已经知道自己要查什么时，从这里进。

如果你现在最想先记住一句话，就记这句：

> 学 Hermes 负责“教你怎么学”，遇到问题负责“帮你定位和排障”，Reference 只负责“查命令、查配置、查工具、查 Skills”。

## 这页主要解决什么

这一页只解决 3 件事：

1. 帮你判断 Reference 到底是干什么的
2. 帮你决定“我要查的内容，该去哪一页 / 哪篇官方原文”
3. 把你和教程页、排障页、解决方案页明确分开

## 🔍 Reference 是什么

Reference 的用户，通常已经知道自己要找什么。

他们来这里不是为了重新学习 Hermes，而是为了快速查：

- 终端里的 `hermes ...` 命令
- 对话里的 `/xxx` 命令
- profile 相关命令
- 环境变量和 API Key 名称
- 内置工具和 toolsets
- MCP 配置结构
- 内置 skills 和可选 skills

所以这一模块的边界很硬：

- 不负责安装排障
- 不负责模型报错排障
- 不负责 Gateway / Messaging 排障
- 不负责 Tools / Skills / MCP 不生效排障
- 不负责 OpenClaw 迁移排障

这些统一交给 [05-遇到问题](../05-遇到问题/01-总览.md)。

## 📚 Reference、教程、排障、解决方案的区别

### 学 Hermes
负责：
- 新手怎么开始
- CLI / Web / 消息入口怎么理解
- 命令和 skills 怎么入门
- profiles / tools / skills 怎么建立认知

### Reference
负责：
- 查命令
- 查参数
- 查环境变量
- 查工具
- 查 toolsets
- 查 MCP 配置
- 查 skills 目录

### 遇到问题
负责：
- 定位问题
- 排查问题
- 按症状分流
- 给 checklist
- 导向官方 FAQ 和 GitHub issues

### 解决方案 / 场景页
负责：
- 某个工作场景怎么落地
- 推荐入口
- 推荐模型
- 推荐路径

一句话记住：

- 教程：教你怎么学
- Reference：让你查表
- 遇到问题：帮你排障
- 解决方案：告诉你怎么落地

## 🗂️ 按使用角色看推荐查法

### 新手最常查
如果你刚开始查表，通常先查这几类：

1. CLI Commands
2. Slash Commands
3. Environment Variables
4. 不确定问题在哪时，直接回 [遇到问题总览](../05-遇到问题/01-总览.md)

### 进阶用户最常查
如果你已经开始搭多助手、多环境或系统能力，通常更常查：

1. Profile Commands
2. Toolsets Reference
3. Built-in Tools Reference
4. MCP Config Reference

### 做方案 / skills / 系统接入的用户最常查
如果你已经在扩展 Hermes 的能力边界，通常更常查：

1. Bundled Skills Catalog
2. Optional Skills Catalog
3. Built-in Tools Reference
4. MCP Config Reference

## 🧠 为什么 Reference 不再维护 FAQ 页

这个模块里不再维护本地 FAQ 页，原因很简单：

- 中文站已经有完整的 [05-遇到问题](../05-遇到问题/01-总览.md)
- 如果再在 Reference 里单独做 FAQ，会出现两套排障入口
- 用户会分不清“我是在查表，还是在排错”
- 官方 FAQ、中文 FAQ、排障页三方也更容易不一致

所以这里的规则已经固定：

- Reference：我知道我要查什么
- 遇到问题：我不知道哪里出错了

## 🔹 官方 FAQ 怎么看

Hermes 官方 Reference 里有 FAQ & Troubleshooting，但中文站已经单独把排障拆到了 05-遇到问题。

所以更推荐的顺序是：

- 中文排障：先看 [05-遇到问题](../05-遇到问题/01-总览.md)
- 官方 FAQ 原文：再看 <https://hermes-agent.nousresearch.com/docs/reference/faq>

这能避免你在“查表”和“排障”之间来回跳错入口。
