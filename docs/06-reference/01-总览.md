# 📚 01-总览｜Reference 参考手册

> 一句话结论：Reference 模块不是教程，也不是排障页，而是 Hermes 官方 Reference 的中文查表入口。你已经知道自己要查什么时，从这里进。

如果你现在最想先记住一句话，就记这句：
> 学 Hermes 负责“教你怎么学”，遇到问题负责“帮你定位和排障”，Reference 只负责“查命令、查配置、查工具、查 Skills”。

## 🔍 Reference 是什么

Reference 的用户，通常已经知道自己要找什么。
他们来这里不是为了重新学习 Hermes，而是为了快速查：
- 终端里的 `hermes ...` 命令
- 对话里的 `/xxx` 命令
- profile 相关命令
- 环境变量和 API Key 名称
- 内置工具和 toolsets
- MCP 配置结构
- 内置 skills 和可选 skills

所以这一模块的边界很硬：
- 不负责安装排障
- 不负责模型报错排障
- 不负责 Gateway / Messaging 排障
- 不负责 Tools / Skills / MCP 不生效排障
- 不负责 OpenClaw 迁移排障

这些统一交给 [05-遇到问题](../05-遇到问题/01-总览.md)。

## 📚 Reference、教程、排障、解决方案的区别

### 学 Hermes
负责：
- 新手怎么开始
- CLI / Web / 消息入口怎么理解
- 命令和 skills 怎么入门
- profiles / tools / skills 怎么建立认知

### Reference
负责：
- 查命令
- 查参数
- 查环境变量
- 查工具
- 查 toolsets
- 查 MCP 配置
- 查 skills 目录

### 遇到问题
负责：
- 定位问题
- 排查问题
- 按症状分流
- 给 checklist
- 导向官方 FAQ 和 GitHub issues

### 解决方案 / 场景页
负责：
- 某个工作场景怎么落地
- 推荐入口
- 推荐模型
- 推荐路径

一句话记住：
- 教程：教你怎么学
- Reference：让你查表
- 遇到问题：帮你排障
- 解决方案：告诉你怎么落地
