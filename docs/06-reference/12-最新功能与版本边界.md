复核日期：**2026-09-30**。官方 latest release 仍是 **Hermes Agent v0.21.5，Git 标签 v2026.9.24**（发布于 2026-09-24 10:09 UTC）。下列条目是与中文教程、桌面使用和国内入口有关的选摘，不是完整 changelog，也不代表已经在你的设备上测试通过。[官方发布说明](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.24)

## 🔎 先确认四个版本信息

| 信息 | 如何理解 | 为什么需要 |
|---|---|---|
| Agent 版本 | v0.21.5 是 Agent 软件版本，v2026.9.24 是其 Git 标签 | 判断后端功能与修复范围 |
| 桌面包版本 | 同一标签的桌面 `package.json` 为 0.17.6；实际下载包以自身版本为准 | 不能把 Agent 版本当作桌面包版本 |
| 安装渠道与提交 | 稳定标签、主干源码、canary 和官网安装器可能不同 | `hermes update` / 重新运行安装器不自动等于锁在本文标签 |
| 连接后端 | 桌面可能连接本机或远端，需分别记录版本 | UI 有入口不等于远端支持对应协议或功能 |

终端可用 `hermes --version` 查看 Agent 版本；桌面核对安装包/应用版本和后端版本。按固定镜像部署时保存完整标签；需要精确复现源码安装时同时记录提交 SHA。[桌面包版本源码](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/apps/desktop/package.json)

### 这些变化如何影响旧工作流

**手动模型 ID**：目录更新慢时，可在桌面选择器使用 **Add custom model… / Custom model…**。先配 provider，再按厂商精确 ID 验证最小回复和实际工具任务；不要将任意名字当成已支持模型。

**Cron 固定模型**：升级后，原先依赖固定任务跨供应商自动兜底的工作流可能改为失败并报告原因。需要跟随默认与全局 fallback 时，先检查任务是否有 pin；取消固定必须是自己明确作出的配置决定。失败通知仍应检查，不能把没有跨供应商切换误判为调度器没有运行。

**缓存与价格**：按[成本实测指南](/docs/start/practical/three-tier-model-routing)比较冷/热会话和账单，未知成本不等于免费，估算也不能替代实际扣费。

### 同一稳定发布窗口中的桌面更新

官方 v0.21.5 发布说明还列出 Simple/Advanced 界面模式、插件 SDK 扩展、Connectors 页面替代旧 MCP 标签、安装插件后让开放聊天使用其工具和技能、快捷键等变化。首次上手先完成模型与文件任务，按需要显示面板或接连接器；不要求为体验新版先安装额外插件。发布说明表示完整整理将随 v0.22.0 提供，本文不将尚未发布的 v0.22.0 当作当前稳定版。[官方稳定版说明](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.24)

## 💻 本地模型：文档和渠道也有版本差异

v2026.9.24 的本地模型文档已描述桌面管理 llama.cpp runtime 与模型下载。2026-09-30 核对的主干文档新增 **Desktop availability and downloads**：Local Models 界面面向 **canary**，其他桌面构建需 `--local` 启动标志，下载与 runtime 来源亦有相应说明。它是主干渠道边界，不应写成所有稳定安装包的统一入口或安装方法。

使用前核对对应版本文档、打包渠道和硬件；本页未下载 runtime 或模型，也没有完成 Windows、Linux、macOS 安装实测。[固定标签本地模型说明](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/website/docs/user-guide/local-models.md)、[主干文档复核快照](https://github.com/NousResearch/hermes-agent/blob/9f2ba1b74de16a9f0aad12a688b33f2b74844608/website/docs/user-guide/local-models.md)

## 🔄 应该怎样升级与验收

1. 先记录桌面包版本、Agent 版本、渠道、profile 与连接后端，并备份配置、会话和必要文件。
2. 明确目标是稳定 release 还是某个主干提交。读其发布/PR 边界，不把同一天合并当成同一个 release。
3. Git 安装、桌面安装器、Docker 的更新方式分别处理；Docker 必须重建容器，见 [VPS 升级步骤](/docs/start/practical/vps-self-hosting)。
4. 复测最小回复、文件产物、当前模型与 profile 默认模型；有 Cron、飞书、钉钉或远程连接时，分别验证自己的实际任务。
5. 记录通过、失败与未验证；未做 API 或国内网络测试时，不能写成“已验证可用”。
