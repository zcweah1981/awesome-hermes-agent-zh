## 🔄 自 v0.21.7 起的源码更新通道

官方仓库的源码安装（`hermes update`，以及 git checkout 上的桌面 updater）默认跟随最新 `vX.Y.Z` stable。当前安装若已经领先 latest，不会降级，会等待后续发行；fork／mirror 仍保持 main。明确需要逐提交更新时，官方提供 `hermes update --set-channel main`，先理解渠道差异再选择。

源码桌面安装可在 **Settings → About → Updates** 选择 **Stable releases / Every commit**；这个开关不改变 Store、MSIX 或 bundled 桌面自身的更新渠道。Store 通过 Store 更新，不能把源码更新命令当作所有包的统一流程。

v0.21.7 当次还修复恢复会话时的 signed thinking 重放与 Bedrock Converse reasoning；main 路线不再多做 release 查询，stable 检查可使用已有 GitHub token，并明确报告 rate limit。遇到 403 或限流先记录当前渠道和原始错误，不为排错新建凭据，也不把这些修复当作国内网络已实测可用。[依据](https://github.com/NousResearch/hermes-agent/releases/tag/v0.21.7)

## 🔎 先确认四个版本信息

| 信息 | 如何理解 | 为什么需要 |
|---|---|---|
| Agent 版本 | 当前稳定版和标签均为 v0.22.2；按完整提交核对 | 判断后端功能与修复范围 |
| 桌面包版本 | 旧 v2026.9.24 源码版本为 0.17.6；v0.21.7 已覆盖桌面发行，实际安装包仍以自身版本为准 | 不能把 Agent 版本或主干 0.0.0 当作桌面发行号 |
| 安装渠道与提交 | 稳定标签、主干源码、canary 和官网安装器可能不同 | `hermes update` / 重新运行安装器不自动等于锁在本文标签 |
| 连接后端 | 桌面可能连接本机或远端，需分别记录版本 | UI 有入口不等于远端支持对应协议或功能 |

终端可用 `hermes --version` 查看 Agent 版本；桌面核对安装包/应用版本和后端版本。按固定镜像部署时保存完整标签；需要精确复现源码安装时同时记录提交 SHA。[桌面包版本源码](https://github.com/NousResearch/hermes-agent/blob/v2026.9.24/apps/desktop/package.json)

## ✅ 已进入 v2026.9.24 稳定标签

这四个 PR 的合并提交已通过 GitHub compare 核验为稳定标签的祖先，不只是根据合并日期推测。

| 变化与官方 PR | 中文用户会看到什么 | 使用边界 |
|---|---|---|
| [#120693：桌面手动添加模型 ID](https://github.com/NousResearch/hermes-agent/pull/120693) | 聊天模型菜单、切换窗口与 Settings 模型选择可输入目录外 ID | 输入精确 ID 并指定 provider；保存到列表不等于账户有调用权限 |
| [#120312：Cron 固定路线不继承全局 fallback](https://github.com/NousResearch/hermes-agent/pull/120312) | 显式固定模型/provider/endpoint 的任务失败时不会偷偷换到全局备用供应商 | 未固定的任务仍可走全局链；同 provider 凭据池轮换与跨 provider fallback 是不同机制 |
| [#120289：恢复会话的跨界面缓存一致性](https://github.com/NousResearch/hermes-agent/pull/120289) | TUI、单次问答与 Gateway 间恢复会话时，工具定义序列保持一致，减少界面切换造成的缓存失配 | 不能保证缓存始终命中；换模型、改工具或供应商缓存规则仍可能改变费用 |
| [#120441：直连 provider 的价格估算补全](https://github.com/NousResearch/hermes-agent/pull/120441) | 部分直连 OpenAI/xAI 等模型不再因缺少本地价表显示未知/零估算 | 这是估算，不是厂商账单；自定义转发、订阅路线或尚无价格数据时仍可能未知 |

### 这些变化如何影响旧工作流

**手动模型 ID**：目录更新慢时，可在桌面选择器使用 **Add custom model… / Custom model…**。先配 provider，再按厂商精确 ID 验证最小回复和实际工具任务；不要将任意名字当成已支持模型。

**Cron 固定模型**：升级后，原先依赖固定任务跨供应商自动兜底的工作流可能改为失败并报告原因。需要跟随默认与全局 fallback 时，先检查任务是否有 pin；取消固定必须是自己明确作出的配置决定。失败通知仍应检查，不能把没有跨供应商切换误判为调度器没有运行。

**缓存与价格**：按[成本实测指南](/docs/start/practical/three-tier-model-routing)比较冷/热会话和账单，未知成本不等于免费，估算也不能替代实际扣费。

### 同一稳定发布窗口中的桌面更新

官方 v0.21.5 发布说明还列出 Simple/Advanced 界面模式、插件 SDK 扩展、Connectors 页面替代旧 MCP 标签、安装插件后让开放聊天使用其工具和技能、快捷键等变化。首次上手先完成模型与文件任务，按需要显示面板或接连接器；不要求为体验新版先安装额外插件。发布说明表示完整整理将随 v0.22.0 提供，这是当时的预告；当前 v0.22 系列已发布，main 独有内容仍按 v0.22.2 说明等待 v0.23.0。[官方稳定版说明](https://github.com/NousResearch/hermes-agent/releases/tag/v2026.9.24)

## 🔄 应该怎样升级与验收

1. 先记录桌面包版本、Agent 版本、渠道、profile 与连接后端，并备份配置、会话和必要文件。
2. 明确目标是稳定 release 还是某个主干提交。读其发布/PR 边界，不把同一天合并当成同一个 release。
3. Git 安装、桌面安装器、Docker 的更新方式分别处理；Docker 必须重建容器，见 [VPS 升级步骤](/docs/start/practical/vps-self-hosting)。
4. 复测最小回复、文件产物、当前模型与 profile 默认模型；有 Cron、飞书、钉钉或远程连接时，分别验证自己的实际任务。
5. 记录通过、失败与未验证；未做 API 或国内网络测试时，不能写成“已验证可用”。
