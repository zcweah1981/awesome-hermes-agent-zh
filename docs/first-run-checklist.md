# 第一次跑不起来时的标准排查顺序

第一次失败不可怕，可怕的是每次都从头乱试。

这篇给你一个固定顺序，让排查变成流程，而不是碰运气。

---

## 标准排查顺序

### 1. 先确认是否安装成功

检查：

```bash
hermes --help
```

如果命令都不存在，先回到安装问题，不要继续看模型配置。

### 2. 再确认 provider 和模型

优先执行：

```bash
hermes model
```

不要一上来手改大量 YAML。

### 3. 再确认 API key

检查：
- key 是否存在
- 变量名是否正确
- 是否放在 `~/.hermes/.env`

### 4. 再确认网络 / 代理 / 证书

如果你在国内网络或公司网络，重点看：
- 代理是否打开
- 证书是否被拦截
- 是否需要 SSL 绕过或证书安装

### 5. 最后再查 custom 配置

只有前面都没问题，才去看 custom endpoint、base_url、模型映射等高级项。

---

## 一个实用原则

先排“基础能力是否存在”，再排“高级配置是否正确”。

也就是：
1. 命令是否存在
2. provider 是否可选
3. key 是否正确
4. 网络是否通
5. 高级配置是否正确
