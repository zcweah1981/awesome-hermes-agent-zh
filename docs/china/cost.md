# 最低成本起步

国内用户真正常问的不是“参数怎么写最全”，而是“怎么用最小预算验证 Hermes 值不值得继续投入”。

## 决策结论

最低成本起步的目标，不是一次把模型、代理、工具链全部配齐，而是用最小投入完成一个可复现的成功闭环。

推荐顺序：

1. 先只准备一个最容易获取的官方 provider
2. 先完成一次最小会话或任务执行
3. 再决定是否要扩模型、扩 provider、扩工作流
4. 不要在验证价值之前就先投入自部署、网关层或多模型矩阵

## 适用场景

### 你在个人环境试用
你最需要的是把预算压低，同时避免自己陷进过度配置。

### 你在帮团队做 PoC
你需要先证明“这个工具能在我们场景里跑起来”，而不是一开始就追求最完整架构。

### 你担心后面会越配越重
那就更应该先控制变量：一个 provider、一个模型、一条任务链，先做出最小成功样本。

## 行动建议

- 先只选一个官方 provider，不要同时铺开三到五家
- 先验证一个你最常用的实际任务，而不是做抽象对比
- 先记录成本、稳定性和可复现性，再决定是否追加预算
- 如果你的目标已经从试用变成长期运行，再去看 [国内 provider 与聚合商](./providers.md) 或 [自托管与私有部署](./self-hosting.md)
