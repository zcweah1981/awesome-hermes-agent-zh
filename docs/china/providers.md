# 国内 provider 与聚合商

这页不是鼓励你把接入层做复杂，而是帮助你判断：什么时候该直接用官方 provider，什么时候才值得补一个国内聚合层或统一入口。

## 决策结论

provider 与聚合商的选择，优先级通常是：

1. 能直接走 Hermes 官方 provider，就先直接走
2. 需要多家模型并行、统一账单或统一出口时，再考虑聚合商
3. 需要团队级统一策略、审计或中转时，再考虑更重的接入层
4. 只有官方 provider 和常见聚合路线都不满足时，再进入 custom endpoint

换句话说，聚合层是为了降低管理复杂度，不应该成为你第一次接触 Hermes 的默认起点。

## 适用场景

### 你在个人环境只用一到两个模型
直接走官方 provider，通常比再套一层聚合更简单也更稳定。

### 你需要在国内环境补齐更多模型可用性
这时聚合商可能有价值，因为它能帮你减少账号和出口碎片化。

### 你要给团队提供统一入口
这时你关心的重点会从“能不能用”转向“怎么统一管理、怎么降低支持成本、怎么减少口径漂移”。

## 行动建议

- 个人试用阶段：优先官方 provider，不必急着引入聚合层
- 多模型并行阶段：先明确你是为可用性、成本还是管理统一而接聚合层
- 团队阶段：先定义统一入口和默认模型，再决定是否保留 custom 补充位
- 如果你发现自己已经开始考虑私有网关、合规隔离或内网模型，继续看 [自托管与私有部署](./self-hosting.md)
