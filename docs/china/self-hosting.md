# 自托管与私有部署

这页不把自部署包装成更高级的默认路线，而是帮你判断：你是真的需要自托管，还是只是因为看到别人这么做就想一步到位。

## 决策结论

只有当你明确遇到下面几类约束时，自托管才值得进入主决策：

- 数据、网络或合规要求决定你不能只依赖公网 API
- 你已经有现成内网模型、私有网关或算力资源
- 团队需要统一接入、可审计、可控的模型出口
- 长期规模化使用下，自建路径的总成本开始优于纯 API 模式

如果你现在还在验证 Hermes 是否适合自己，那么自托管通常不是第一步。

## 适用场景

### 你在做个人试用
这类场景通常不需要先上自部署，否则你会把验证工具价值和搭基础设施混在一起。

### 你在企业或团队环境做落地
这时自托管可能有现实意义，因为问题不再只是模型好不好用，而是账号治理、数据边界和统一运维。

### 你已经有现成推理服务
如果你已有内网 vLLM、SGLang 或兼容网关，那么 Hermes 可以作为上层入口接入，但仍应先做最小试点验证。

## 行动建议

- 先判断你面对的是合规问题、成本问题还是运维统一问题
- 先做最小试点，不要一开始就全量迁移到私有部署
- 先保留官方 provider 作为对照组，再评估自托管是否真的更优
- 如果你最终只是需要一个补充接入位，而非完整私有化，可先回看 [国内 provider 与聚合商](./providers.md) 或 [custom OpenAI-Compatible 参考页](../custom-openai-compatible.md)
