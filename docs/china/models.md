# 国内模型选择

这页不追求列满所有模型，而是先回答中国用户最常见的问题：现在该先选谁，什么场景再换，什么时候不要一开始就走自定义配置。

## 决策结论

国内模型的默认判断顺序可以先按这四类：

- 想最快跑通且控制成本：优先考虑 DeepSeek 路线
- 想要更强中文表达或企业体系兼容：优先看 Qwen / 阿里云体系
- 想补充综合能力与国内替代：可评估 GLM / z.ai
- 想做长文本、写作或代码辅助：可评估 Kimi

核心原则只有一句：优先选 Hermes 已有官方 provider 的模型路径，只有官方没覆盖时，才考虑 custom endpoint。

## 适用场景

### 你现在只有一个目标：先跑起来
不要先比较一长串 benchmark。先选一个最容易拿到密钥、最容易验证、最容易排障的模型，把 Hermes 跑通再说。

### 你已经开始考虑团队长期使用
这时你要看的不只是模型能力，还要看是否方便采购、是否容易统一账号、是否方便后续扩展到更多角色与工作流。

### 你在纠结要不要直接走 custom provider
如果官方 provider 已经覆盖你要用的模型，那 custom 只会增加维护成本，不会给你带来真正的第一步优势。

## 行动建议

- 只想先成功一次：先从 DeepSeek 或 Qwen 路线开始
- 更重视中文写作、企业上下文或云体系配套：优先评估 Qwen / 阿里云
- 需要补充国内备选和多路径冗余：加入 GLM / z.ai 评估
- 需要长文本、代码辅助或写作体验：把 Kimi 放进候选
- 当你已经确定官方 provider 不够用，再转到 [custom OpenAI-Compatible 参考页](../custom-openai-compatible.md)
