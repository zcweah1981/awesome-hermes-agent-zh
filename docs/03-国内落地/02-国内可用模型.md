# 02-国内可用模型

在国内使用 Hermes，模型选型不是越多越好，而是先选一条最适合你当前阶段的默认路线。
如果你一开始就在很多模型之间反复横跳，通常只会把真正的上手判断拖慢。

## 第一轮默认建议

如果你是第一次用 Hermes，第一轮更应该优先选择一条稳定、可持续、容易继续排查问题的模型路线。
先解决“能不能稳定用起来”，再考虑“能力上限是不是最强”。

对大多数第一次进入 Hermes 的用户来说，第一轮模型选择的目标不是做一场大评测，而是先得到一条可持续使用的默认路线：

- 输出质量足够稳定
- 成本在可接受范围内
- 出问题时容易判断原因
- 后续如果要升级，不需要把整个路径全部推翻

## 模型选择的核心标准

选模型时，先看这几个维度，而不是先看模型名字是否热门：

- 稳定性：你是不是能连续几次得到大致可靠的结果
- 成本：这条路线能不能支撑你至少持续试用一段时间
- 任务匹配度：你是偏内容、偏通用助手，还是偏代码和自动化
- 后续扩展性：当你以后要升级入口、接 Provider 或做团队协作时，这条模型路线会不会成为阻碍

真正有用的模型选择，应该服务于你当前的 Hermes 使用目标，而不是服务于“我想把所有热门模型都试一遍”的冲动。

## 按场景推荐模型路线

如果你现在还没有非常明确的技术偏好，可以先按场景判断：

- 内容生产：优先看中文表达、长文稳定性、连续输出质量
- 通用助手：优先看综合能力和成本平衡，不要一开始就追求最强参数
- 代码 / 自动化：优先看结构化输出、执行指令稳定性、工具调用配合度
- 预算敏感：优先看成本可控和持续可用，而不是短时间冲高配置

这里的重点不是给你一个“唯一答案”，而是帮你先缩小判断范围。
如果你已经知道自己主要是内容场景，就没有必要先按代码场景的标准选模型；反过来也一样。

## 什么时候需要升级或更换

只有在你已经明确遇到瓶颈时，才值得升级或更换模型。
常见的升级信号包括：

- 当前模型在你的主要任务上明显不稳定
- 成本已经不适合继续使用
- 你已经确认要长期使用，且当前能力上限开始拖慢效果
- 你已经知道自己需要更强的结构化输出、代码支持或长文能力

如果你现在还处于“刚刚用起来”的阶段，频繁换模型通常不会让事情更快，反而会让你分不清问题到底来自模型、Provider，还是自己的使用方式。

## 常见误区

模型选型里最常见的误区有：

- 一开始就同时试很多模型，结果没有一条真正用顺
- 把模型选择和 Provider 选择混成一回事
- 只看社区热度，不看自己当前到底要解决什么任务
- 还没稳定使用，就急着追求最高配置

如果你已经踩中了其中一条，最好的做法通常不是继续加复杂度，而是先退回到一条更容易持续使用的默认路线。
