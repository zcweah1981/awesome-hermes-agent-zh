# 从哪里进入 Hermes

国内使用 Hermes，不同用户最先适合的入口方式并不一样。
CLI、WebUI、API 和网关，分别适合不同阶段和目标；真正需要解决的不是“哪个听起来更高级”，而是“哪一种最适合你现在开始用”。

## 四种入口方式总览

你通常会在这几类入口之间做选择：

- CLI：最直接，最适合自己先用、先判断 Hermes 真实使用感受
- WebUI：更适合希望用界面降低门槛的人
- API server：适合已经开始考虑把 Hermes 接到别的系统里的人
- gateway：适合消息平台、多入口接入或更复杂协作场景

它们之间不是“功能等级”关系，而是不同阶段的入口选择。
第一次进入 Hermes 时，最重要的通常不是一步到位，而是先选一个最容易验证价值、最容易看清问题的入口。

## 默认推荐顺序

如果你是第一次用 Hermes，默认建议顺序是：

1. 先从最直接、最容易判断问题的入口开始
2. 只有在你已经确认会持续使用时，再升级到更复杂的共享或系统级入口
3. 不要为了“以后可能会用到”而一开始就选最复杂的入口

这个顺序能帮你把注意力放在 Hermes 本身，而不是过早被接入方式带偏。

## 按用户目标分流

如果你当前的目标不同，入口方式的优先级也不同：

- 我只想自己先用起来：优先看最直接、最容易开始的个人入口
- 我想让团队成员也能用：优先看共享成本更低的入口
- 我想把 Hermes 接进外部系统：优先看 API server 路线
- 我想后续做自动化或服务化：优先看更可扩展的系统级入口

入口方式不是越复杂越好，而是越符合当前阶段越好。
如果你现在的目标还只是“我自己先真正用起来”，那就没必要一开始就把入口升级成团队或系统级方案。

## 什么时候升级入口

只有在这些情况出现时，才值得升级入口方式：

- 你已经确认个人入口不够用了
- 你准备把 Hermes 给团队成员使用
- 你需要把 Hermes 接到外部系统或自动化流程里
- 你已经明确知道为什么需要 API 或网关，而不是只是觉得它们听起来更专业

升级入口的前提，不是功能想象，而是你已经有了更强的真实使用需求。
