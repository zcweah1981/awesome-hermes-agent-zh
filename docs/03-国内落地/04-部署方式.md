# 🚀 04-部署方式

国内使用 Hermes 时，很多人一上来就把部署问题想得太复杂。
真正需要解决的是：你现在到底该把 Hermes 跑在哪里，才能让它先稳定用起来，而不是先把自己拖进一套过重的运维体系。

## 部署方式总览

你通常会在这几类路径之间做选择：

- 本地运行：最适合第一轮试用、快速验证和熟悉基本使用方式
- 云主机：适合希望更稳定在线、随时可访问、后续还能继续扩展的人
- 托管方案：适合不想自己承担太多环境维护成本的人
- 更复杂的自建环境：适合已经明确知道自己为什么需要更多控制权的人

它们之间不是“谁更专业”的关系，而是“谁更适合你现在的目标”的关系。
第一次进入 Hermes 时，选一条更容易开始、更容易持续验证的路径，通常比选一条看起来更完整的复杂方案更重要。

## 默认起步建议

如果你是第一次用 Hermes，默认建议非常直接：

- 先从最容易验证结果、最容易判断问题的环境开始
- 先让 Hermes 真正进入使用，而不是先把部署做成一个独立项目
- 只有在确认你需要更长时间运行、更稳定在线或更高控制权时，再升级部署方式

大多数情况下，第一轮部署的目标应该是“先让自己持续用起来”，而不是“提前为未来所有可能性做重型准备”。

## 按使用目标选部署方式

如果你当前的目标不同，部署方式的优先级也不同：

- 个人第一次试用：优先选最轻量、最容易开始的路径
- 长期开机个人助手：优先选稳定在线、维护成本可接受的路径
- 小团队内部使用：优先看可持续维护与多人共享的便利性
- 未来想做 API 服务化：优先考虑后续扩展空间，而不是只看眼前是否能跑

判断部署方式时，不要只问“能不能跑”，还要问“这条路是不是我接下来一个阶段都愿意维护”。

## 什么时候升级复杂度

只有在这些情况出现时，才值得升级部署复杂度：

- 当前路径已经明显不够稳定
- 你已经确认 Hermes 会长期运行
- 你需要更高的在线可用性或更强的控制权
- 你后面准备把 Hermes 接入 API、网关或团队级使用场景

如果你还处在“先验证好不好用”的阶段，过早升级部署复杂度，通常只会让你把注意力从 Hermes 本身转移到环境折腾上。

## 典型误区

部署路径上最常见的误区有：

- 还没稳定用起来，就先研究完整运维方案
- 把“更复杂”误当成“更适合长期”
- 把云厂商、运维工具、环境细节一次性全部拉进第一轮决策
- 还没确认自己会不会持续使用，就先做重型部署投入

如果你已经出现这些倾向，通常最值得做的不是继续加配置，而是退回到一条更轻、更容易持续使用的路径。
