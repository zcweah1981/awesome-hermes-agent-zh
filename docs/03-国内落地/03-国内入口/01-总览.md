# 01-总览

如果你已经决定在国内环境里使用 Hermes，接下来最容易卡住的往往不是“买哪家模型”，而是：**我到底应该从哪里进入 Hermes。**

这个模块只解决一件事：帮你先把“入口”选对。

- 想先把配置、排错和模型切换都握在手里 → 先看 CLI
- 想给团队做统一触达 → 看飞书、企业微信、钉钉、个人微信这类 Gateway 入口
- 想做网页前端 → 先分清 Dashboard 和 API Server，不要把它们当成一回事

## 🎯 这一模块到底讲什么

入口模块负责回答：**你从哪里用 Hermes。**

它不重复讲：

- 模型怎么买、怎么计费
- 云服务器怎么买、怎么部署
- 各家模型套餐到底值不值

这模块真正要做的是，把入口分成几类讲清楚：

- **CLI**：最完整、最适合排错和配置的第一主入口
- **Dashboard**：管理面板，不是聊天前端
- **API Server + Open WebUI**：真正的“前端 + 后端”组合
- **飞书 / 企业微信 / 钉钉 / 个人微信**：消息入口，优先服务团队触达

## 🧭 先看核心判断

在进入具体页面之前，先记住这 4 个判断：

1. **Dashboard 是管理面板，不是聊天前端。**
2. **API Server 才是 Open WebUI 等前端真正连接的后端。**
3. **CLI 是最完整、最适合排错和配置的第一主入口。**
4. **飞书、企业微信、钉钉、个人微信都属于 Gateway 消息入口。**

如果这 4 句没先分清，后面你很容易把“管理面板”“聊天前端”“消息网关”“底层服务”全混在一起。

## 📊 国内入口怎么选

| 入口 | 本质 | 最适合谁 | 你现在最该怎么理解 |
|---|---|---|---|
| Dashboard | 管理面板 | 想看会话、任务、状态与配置管理的人 | 它是控制台，不是主要聊天前端 |
| API 服务与 Open WebUI | 后端服务 + 网页前端 | 想让浏览器里的聊天界面连到 Hermes 的人 | Open WebUI 连的是 API Server，不是 Dashboard |
| 命令行（CLI） | 原生主入口 | 想先把 Hermes 跑顺、排错、切模型、改配置的人 | 默认第一入口 |
| 飞书 | Gateway 消息入口 | 想让团队先在飞书里触达 Hermes 的人 | 适合团队内部通知、问答、轻量使用 |
| 企业微信（AI Bot） | Gateway 消息入口 | 企业微信已经是主协作平台的团队 | 重点是企业内协作触达 |
| 钉钉 | Gateway 消息入口 | 已经用钉钉做办公与审批流的团队 | 适合接进现有组织沟通流 |
| 个人微信 | Gateway 消息入口 | 想把 Hermes 放进个人微信触达链路的人 | 重点不是配置最标准，而是个人触达最直接 |

## ✅ 最短决策

如果你只想快速决定先看哪一页，按这个顺序走：

### 1）你是第一次用 Hermes
先看：[04-命令行（CLI）](./04-命令行（CLI）.md)

因为 CLI 是最完整、最适合排错、最适合先把模型和配置跑通的入口。只要 CLI 没跑顺，后面你接 Dashboard、Open WebUI 或消息平台，排错成本都会更高。

### 2）你想做网页聊天界面
先看：[03-API 服务与 Open WebUI](./03-API 服务与 Open WebUI.md)

因为真正该先理解的是：

- Hermes 的后端服务怎么暴露
- Open WebUI 这样的网页前端怎么接进来
- Dashboard 和网页聊天前端到底是不是一回事

### 3）你想看管理面板
先看：[02-网页控制台（Dashboard）](./02-网页控制台（Dashboard）.md)

但你要先带着一个前提进去：

- 这是控制台 / 管理面板
- 不是“用来替代 CLI 的万能聊天前端”

### 4）你想先给团队接入消息平台
看：[05-飞书](./05-飞书.md) / [06-企业微信（AI Bot）](./06-企业微信（AI Bot）.md) / [07-钉钉](./07-钉钉.md) / [08-个人微信](./08-个人微信.md)

这几页的共同点不是“哪个聊天框更好看”，而是：

- 你怎么把 Hermes 变成一个团队成员能直接触达的入口
- 你怎么借消息平台做通知、问答和轻量交互
- 你怎么让 Hermes 从“你自己会用”变成“别人也能用”

## 🔍 最容易搞混的 3 件事

### 1. 把 Dashboard 当成 Open WebUI
这是最常见的误区。

- **Dashboard** 解决的是“管理、查看、控制”
- **Open WebUI** 这类前端解决的是“聊天界面”
- 这两者不是同一个东西

### 2. 还没跑顺 CLI，就急着接消息平台
如果连 CLI 都没先跑通，消息入口一旦出问题，你会很难判断：

- 是模型问题
- 是配置问题
- 是 Gateway 问题
- 还是平台权限问题

所以大多数情况下，CLI 仍然应该先于消息入口。

### 3. 把“入口选择”和“模型选择”混为一谈
入口模块只决定：

- 你从哪里用 Hermes
- 你怎么触达 Hermes

模型模块才决定：

- 你接哪家模型
- 你怎么买模型
- 你走按量、订阅还是兼容接口

这两层不要在脑子里混成一件事。

## 🧱 这一模块后续会覆盖什么

接下来这一模块会按下面顺序逐页展开：

1. 网页控制台（Dashboard）
2. API 服务与 Open WebUI
3. 命令行（CLI）
4. 飞书
5. 企业微信（AI Bot）
6. 钉钉
7. 个人微信

这里的顺序不是“唯一使用顺序”，而是为了把概念边界先理顺：

- 先分清管理面板、后端服务、原生命令行
- 再进入具体消息平台入口

## 🏁 默认建议

如果你完全不想自己判断，直接按这个默认主线走：

1. 先回部署页，确认环境已经具备运行条件
2. 再看模型页，确认你已经有可用模型入口
3. 然后从 **CLI** 开始，把 Hermes 先跑顺
4. 最后再根据需要接 Dashboard、Open WebUI 或消息平台

这条顺序最稳，因为它把“部署 → 模型 → 入口”三层拆开了。

## ❓FAQ

### 1. 国内入口这一模块到底在解决什么问题？
它只解决一件事：

- 你从哪里开始用 Hermes
- 你后面要接的是 CLI、管理台、网页前端，还是消息入口

它不是模型购买页，也不是云部署购买页。

### 2. 为什么总览页一上来就强调 CLI？
因为从 Hermes 官方文档体系看：

- CLI 是最完整的原生入口
- 很多后续入口的排错最终都会回到 CLI
- 如果 CLI 没跑顺，后面加 Dashboard、Open WebUI、飞书、企业微信、钉钉、个人微信，只会叠更多排错层

### 3. Dashboard 和 Open WebUI 为什么要拆成两页看？
因为它们在官方能力边界里不是一回事：

- Dashboard = 管理台
- Open WebUI = 浏览器聊天前端
- API Server = Open WebUI 真正连接的后端

### 4. 消息平台入口是不是都该比 CLI 更后做？
默认是。

因为消息平台页解决的是“触达层”，不是“本体层”。
更稳的顺序仍然是：

- 先把 CLI 跑顺
- 再决定接管理台、网页前端或消息平台

## ⚠️ 风险点与默认建议

### 1. 不要把“入口选择”当成“模型选择”
入口模块只决定：

- 从哪里用 Hermes
- 先打通哪一层

模型模块才决定：

- 接哪家模型
- 怎么买
- 走按量、订阅还是兼容接口

### 2. 不要还没跑顺 CLI 就急着接别的入口
这是前半段最容易造成返工的地方。

如果 CLI 没跑顺：

- Dashboard 里的状态很难判断
- Open WebUI 的前后端问题更难拆开
- 飞书 / 企业微信 / 钉钉 / 个人微信 的入口异常也会一起叠上来

### 3. 默认建议：按“CLI → 管理台 / API 前端 → 消息平台”顺序走
如果你不想自己判断，最稳的默认主线就是：

1. 先看 [04-命令行（CLI）](./04-命令行（CLI）.md)
2. 再按需要进入 [02-网页控制台（Dashboard）](./02-网页控制台（Dashboard）.md) 或 [03-API 服务与 Open WebUI](./03-API 服务与 Open WebUI.md)
3. 最后再进入飞书、企业微信、钉钉、个人微信这类消息入口
