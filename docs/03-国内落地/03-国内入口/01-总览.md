# 03-国内入口 | 总览

这一页在“国内落地”闭环里只解决一件事：先帮你选对 Hermes 的使用入口，再进入正确的入口页面。

## 🧭 先按你的当前状态分流

| 目标页面 | 解决什么 | 推荐下一页 |
|---|---|---|
| [04-命令行（CLI）](./04-命令行（CLI）.md) | 适合第一次真正开始用 Hermes、排错、切模型、改配置的人 | 默认先看这一页 |
| [03-API 服务与 Open WebUI](./03-API%20%E6%9C%8D%E5%8A%A1%E4%B8%8E%20Open%20WebUI.md) | 适合想做浏览器聊天前端的人 | 如果你明确需要网页聊天界面，优先看这一页 |
| [02-网页控制台（Dashboard）](./02-网页控制台（Dashboard）.md) | 适合想看配置、状态、日志、会话管理的人 | 如果你要的是管理面板，优先看这一页 |
| [05-飞书](./05-飞书.md) / [06-企业微信（AI Bot）](./06-%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%EF%BC%88AI%20Bot%EF%BC%89.md) / [07-钉钉](./07-钉钉.md) / [08-个人微信](./08-个人微信.md) | 适合想把 Hermes 放进团队或个人消息触达链路的人 | 先把 CLI 跑顺后，再进入对应消息平台页 |

如果你只记一句：

- 第一次真正开始用 Hermes → 先看 CLI
- 想做网页聊天前端 → 先看 API 服务与 Open WebUI
- 想看管理面板 → 看 Dashboard
- 想接团队消息平台 → 先跑顺 CLI，再进飞书 / 企业微信 / 钉钉 / 个人微信

## 💬 这些入口到底怎么分

### 1. CLI：第一主入口
优先看：[04-命令行（CLI）](./04-命令行（CLI）.md)

适合：

- 第一次开始真正使用 Hermes
- 需要排错、切模型、改配置
- 想先拿到一个最稳定的可验证闭环

### 2. API 服务与 Open WebUI：网页前端路线
优先看：[03-API 服务与 Open WebUI](./03-API%20%E6%9C%8D%E5%8A%A1%E4%B8%8E%20Open%20WebUI.md)

适合：

- 想让浏览器聊天界面连上 Hermes
- 想先分清前端和后端分别是什么

### 3. Dashboard：管理面板路线
优先看：[02-网页控制台（Dashboard）](./02-网页控制台（Dashboard）.md)

适合：

- 想看会话、任务、状态、配置管理
- 但要先记住：Dashboard 是管理面板，不是聊天前端

### 4. 飞书 / 企业微信 / 钉钉 / 个人微信：消息入口路线
优先看：

- [05-飞书](./05-飞书.md)
- [06-企业微信（AI Bot）](./06-%E4%BC%81%E4%B8%9A%E5%BE%AE%E4%BF%A1%EF%BC%88AI%20Bot%EF%BC%89.md)
- [07-钉钉](./07-钉钉.md)
- [08-个人微信](./08-个人微信.md)

适合：

- 想把 Hermes 从“自己可用”推进到“别人也能用”
- 想让 Hermes 进入团队协作流或个人消息触达链路

## ⭐ 默认主线

如果你完全不想自己判断，默认先走这条线：

1. [04-命令行（CLI）](./04-命令行（CLI）.md)
2. 跑顺后再回到 [03-国内落地总览](../01-总览.md)
3. 再按需要进入网页前端或消息平台对应页

为什么默认先推 CLI：

- 它是最完整的原生入口
- 它最适合排错和配置
- 后续无论接网页前端还是消息平台，最终都更容易回到 CLI 判断问题在哪一层

## ✅ 看完这页你应该能立刻判断什么

看完国内入口总览，你应该能直接回答这 3 个问题：

1. 我应该先用 CLI、网页前端，还是消息平台？
2. 我下一页应该先点哪个入口页？
3. 我是不是把“管理面板”“网页前端”“消息平台”“原生主入口”混成一件事了？
