# 国内模型总览

如果你已经把 Hermes 跑起来，接下来最重要的不是“谁最强”，而是先决定你要走哪一类模型路径。

这页只帮你做一件事：把 Hermes 原生 provider、聚合型订阅、单厂商订阅和按量 API 先分清，再告诉你默认从哪条路起步。

## 🚀 国内模型核心路径指引

![国内模型总览路线图](./assets/models-overview-hero-v1.png)

## 先看结论：先选路径，不先选品牌

国内这批主流方案，已经很清楚地分成三类：

| 路线 | 本质 | 适合谁 | 代表项 |
|---|---|---|---|
| Hermes 原生支持的 provider | 直接接到 Hermes 的常规路径 | 想先把 Hermes 跑顺的人 | GLM / z.ai / zai、Kimi / Moonshot、Kimi / Moonshot China、MiniMax、MiniMax China、Alibaba Cloud / DashScope / Qwen、DeepSeek、Custom endpoint |
| 聚合型 Coding / Token 套餐 | 一份订阅里切多家国产模型 | 想把“选择”交给套餐的人 | 阿里云百炼 Coding Plan、腾讯云 Token Plan |
| 单厂商订阅或按量 API | 单家模型的订阅或接口能力 | 已经认准某一家的人 | GLM Coding Plan、MiniMax Token Plan、Kimi Code、DeepSeek API、Kimi API |

这页最重要的结论不是“谁最强”，而是：

**先决定你要的是 Hermes 原生 provider、聚合订阅，还是按量 API。**

## 如果你的目标是“先把 Hermes 跑顺”

如果你是 Hermes 中文站的主线用户，默认优先级不应该完全照第三方对比文章来，而是先看 Hermes 直接支持得最顺的那批 provider。

这意味着，如果你的目标是：

- 先把 Hermes 连上
- 先跑通一次稳定对话
- 先让站内教程更简单

那优先顺序应该更偏向：

1. **按量计费接口**（如 DeepSeek）
2. **聚合型 Coding / Token 套餐**
3. **单厂商订阅**
4. **自定义兼容接口**

## 先按人群分流，而不是先按厂商分流

### 你只想先跑起来，先别买月付包
优先看 **[DeepSeek 按量计费接口](./07-DeepSeek按量计费接口.md)**，其次再看 **[Kimi 登月计划](./06-Kimi登月计划.md)** 里的按量路线。

### 你想一份订阅里切多家模型
优先看 **[阿里云百炼编程套餐](./02-阿里云百炼Token plan.md)** 和 **[腾讯云 Token Plan](./03-腾讯云Token Plan.md)**。

### 你已经认准某一家
那就不要在总览页里继续犹豫。

- 认准智谱 → 走 **[智谱 GLM Coding Plan](./04-智谱GLM Coding Plan.md)**
- 认准 MiniMax → 走 **[MiniMax Token Plan](./05-MiniMax Token Plan.md)**
- 认准 Kimi 的 Coding 体验 → 走 **[Kimi 登月计划](./06-Kimi登月计划.md)**

### 你主要做 Hermes，不是主要做 Claude Code / OpenClaw
这种情况下，优先级要再收紧一层。

腾讯云令牌套餐更适合做“AI编程工具生态扩展路线”，如果不熟悉，优先从按量接口起步。
