# 03-国内落地

如果你在中国境内使用 Hermes，真正的难点通常不在“会不会装”，而在“先怎么选”。
这一模块不是单篇配置教程，而是先帮你把模型、Provider、部署、成本和入口方式这些关键决策理顺，再进入具体动作。

## 什么是国内落地

“国内落地”解决的不是某一个配置技巧，而是中国用户第一次使用 Hermes 时最容易卡住的关键决策。
你不需要一上来研究全部技术细节，但要先知道自己应该先选什么、后选什么，避免把时间浪费在错误的复杂路径上。

## 你在国内真正要做的 5 个决策

在国内开始用 Hermes，通常会先遇到这 5 个问题：

- 模型怎么选：先追求稳定、便宜，还是先追求能力上限？
- Provider / 兼容接口怎么选：是直接走最稳路径，还是已经有必须兼容的上游入口？
- Hermes 跑在哪里：先本地试、放到云主机，还是走更长期的运行环境？
- 怎么用最低成本开始：只想验证能不能用，还是已经准备长期投入？
- 先从 CLI、WebUI、API 还是网关进入：你是自己先用，还是从一开始就准备给团队或系统接入？

这 5 个问题不是分散的配置点，而是一条完整决策链。先把顺序想清楚，后面每一步都会更稳。

## 默认推荐起步路径

如果你是第一次用 Hermes，默认建议按这个顺序判断：

1. 先看自己是不是预算敏感，明确能接受的最低成本路径
2. 再决定第一轮模型路线，不要一上来在多个模型之间反复横跳
3. 再决定 Provider / 兼容接口怎么接
4. 最后再判断 Hermes 跑在哪里、以及从哪个入口开始用

这样做的好处是：你不会因为先研究复杂部署或兼容接口，而把真正影响第一轮体验的选择拖慢。

## 如果你只想最快跑起来

如果你现在的目标只有一个：先在国内把 Hermes 稳定跑起来，那就用最简单的思路处理：

- 先选一条成本可控、可持续使用的默认路线
- 先避免引入太多中间层
- 先选最容易判断问题的使用入口
- 等你确认 Hermes 真的进入日常使用，再回头升级模型、部署或接入方式

对大多数第一次接触 Hermes 的用户来说，先“跑起来并持续可用”，比先“做一套最灵活的架构”更重要。
