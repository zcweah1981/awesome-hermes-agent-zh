# 03-国内落地 | 总览

这一页在整个“国内落地”闭环里只解决一件事：先判断你现在卡在“部署”“模型”还是“入口”，再进入正确的二级、三级页面。

国内落地真正要拆开的，是 3 个层次不同的问题：

1. 先把 Hermes 放到哪里跑
2. 再把 Hermes 接到哪类模型入口
3. 最后决定你从哪里真正使用 Hermes

## 🎯 为什么需要“国内落地”

Hermes 的默认体验基于全球通用开源环境，但国内用户真正落地时，最常卡住的往往不是功能本身，而是下面 3 类现实问题：

1. **网络与环境**：机器放在哪、哪家云厂商更适合你的起步路线
2. **模型与成本**：先按量跑通、先买套餐，还是直接复用已有兼容接口
3. **触达与交互**：最终是从 CLI 用、从网页前端用，还是接入飞书、企业微信、钉钉、个人微信

所以“国内落地”不是一个大杂烩模块，而是把这三层决策拆开，让你少走弯路。

## 🧱 二级模块之间到底是什么关系

不要把这 3 层混成一件事，它们分别解决的是不同问题：

| 层级 | 你在做什么决定 | 典型问题 |
|---|---|---|
| 国内部署 | 先把 Hermes 放到哪里跑 | 我先上阿里云还是腾讯云？ |
| 国内模型 | 先把 Hermes 接哪类模型入口 | 我先按量跑通，还是先买套餐？ |
| 国内入口 | 先决定从哪里真正使用 Hermes | 我先用 CLI、网页前端，还是消息平台？ |

所以更稳的默认顺序不是乱跳，而是：

1. 部署
2. 模型
3. 入口
