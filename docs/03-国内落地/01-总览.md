# 国内落地

如果你准备在中国境内使用 Hermes，这一模块不要再只纠结“买哪家模型”。真正更稳的顺序是先把三层拆开：

1. 先决定怎么部署
2. 再决定怎么接模型
3. 最后决定从哪个入口使用 Hermes

这一页的作用，就是按已经落地完成的二级、三级模块，把整条国内路径一次讲清楚。

## 🎯 这一模块现在分成哪 3 个二级模块

| 二级模块 | 解决什么问题 | 你什么时候先看它 |
|---|---|---|
| [01-国内部署](./01-国内部署/01-总览.md) | 先把机器、环境、云厂商路径选对 | 你还没把 Hermes 放到一台稳定可用的国内机器上 |
| [02-国内模型](./02-国内模型/01-总览.md) | 先把模型入口、套餐路线、按量/订阅/兼容接口选对 | 你已经能部署，接下来要决定模型怎么买、怎么接 |
| [03-国内入口](./03-国内入口/01-总览.md) | 先把“从哪里用 Hermes”选对 | 你已经有部署和模型基础，接下来要决定用 CLI、网页前端还是消息平台 |

如果你只记一句：

- 没机器、没环境 → 先看国内部署
- 有机器了，但还没想好模型 → 先看国内模型
- 部署和模型都差不多了，想真正开始用 → 先看国内入口

## 🧱 二级模块之间到底是什么关系

不要把这 3 层混成一件事，它们分别解决的是不同问题：

| 层级 | 你在做什么决定 | 典型问题 |
|---|---|---|
| 国内部署 | 先把 Hermes 放到哪里跑 | 我先上阿里云还是腾讯云？ |
| 国内模型 | 先把 Hermes 接哪类模型入口 | 我先按量跑通，还是先买套餐？ |
| 国内入口 | 先决定从哪里真正使用 Hermes | 我先用 CLI、网页前端，还是消息平台？ |

所以更稳的默认顺序不是乱跳，而是：

1. 部署
2. 模型
3. 入口
