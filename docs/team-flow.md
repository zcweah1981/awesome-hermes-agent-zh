# 多 Agent 协作：适合什么场景

Hermes 不只适合单个 Agent 对话，也适合把任务拆给不同角色来协作完成。

这一页不讲内部实现细节，只帮助你判断：
- 什么场景适合多 Agent
- 多 Agent 能带来什么价值
- 应该怎么开始

---

## 什么是多 Agent 协作

你可以把 Hermes 理解成一个可以分工的 AI 工作台。

例如：
- 一个 Agent 负责拆任务
- 一个 Agent 负责写代码
- 一个 Agent 负责测试
- 一个 Agent 负责整理输出

这样做的目的不是“看起来高级”，而是让复杂任务更容易拆解、更容易验证，也更容易扩展。

---

## 适合的场景

### 1. 软件开发
- 需求拆解
- 代码实现
- 测试与修复
- 发布前检查

### 2. 内容生产
- 选题整理
- 资料收集
- 初稿生成
- 分发改写

### 3. 运营自动化
- 信息抓取
- 数据整理
- 摘要生成
- 定时推送

### 4. 团队知识工作
- 会议纪要整理
- 项目日报生成
- 文档检查与更新

---

## 为什么要用多 Agent

### 更容易拆任务
复杂问题被拆成多个更清晰的小任务。

### 更容易控质量
每个角色只负责一段工作，结果更容易检查。

### 更容易扩展
你可以先从 1 个 Agent 开始，后面再加到 2 个、3 个，甚至更多。

---

## 推荐起步方式

不要一上来就做很复杂的团队系统。

建议按这个顺序：

1. 先跑通单 Agent
2. 再增加一个“执行型 Agent”
3. 最后再加测试、审核、分发等角色

如果你还没跑通基础环境，请先回到：
- [快速开始](./quick-start.md)
- [模型与 Provider](./models.md)

## 一个最简单的协作例子

你要完成一个小功能开发，可以这样分工：
- Agent A：整理需求
- Agent B：完成代码
- Agent C：检查结果并补充说明

这类方式特别适合：
- 长任务
- 多步骤任务
- 需要反复校验的任务

---

## 什么时候不需要多 Agent

如果你的任务只是：
- 一次简单问答
- 一段小脚本修改
- 单文件查询

那么单 Agent 往往更直接。

原则很简单：
任务越复杂，越适合拆；任务越简单，越适合直接做。
