# 从 OpenClaw 过来

这是 RM6 的正式主入口。

这一组页面不再只回答“要不要迁”，还要把“怎么迁、能不能先共存、哪些内容先别迁”讲清楚，让 OpenClaw 用户能按最小风险进入 Hermes。

## 这组内容解决什么

如果你已经在用 OpenClaw，最常见的不是技术不会，而是顺序容易错：
- 一上来就全量迁移
- 先迁抽象框架，不迁真实场景
- 旧系统还没切边界，就急着重做新系统

RM6 的目标，就是把迁移判断、能力对比、共存策略拆成 3 条清晰路径。

## 三条正式路径

### 1. 先判断值不值得迁
- 入口：[怎么选，怎么迁](./compare.md)
- 适合谁：还在比较 Hermes 和 OpenClaw，不确定现在是否该迁
- 解决什么：先判断收益、成本和适用场景

### 2. 再决定按什么顺序迁
- 入口：[先判断，再迁移](./migration.md)
- 适合谁：已经确认要迁，但想避免一次性重构
- 解决什么：给出最稳的迁移顺序、试点方式和最小迁移清单

### 3. 需要先共存，不要硬切
- 入口：[先共存，再替换](./coexist.md)
- 适合谁：旧工作流还在跑生产，短期不能停
- 解决什么：明确哪些能力适合先接入 Hermes，哪些能力应继续留在 OpenClaw

## 推荐顺序
1. 先看 [怎么选，怎么迁](./compare.md)
2. 再看 [先判断，再迁移](./migration.md)
3. 如果你不能停旧系统，补看 [先共存，再替换](./coexist.md)
